### 1.2 축소와 복원은 서로 다른 질문이다 (2026-08-09 재정리)

초판은 D1을 "분모를 줄일 것인가" 하나로 묶었다. 그것이 틀렸다. **레지스트리 미러를 내리는 것(축소)과 부동산을 간판으로 세우는 것(복원)은 방향이 반대인 두 작업**이고, 둘 다 해야 한다. 하나만 하면 각각 실패한다.

#### 왜 두 개인가 — 매물은 편의점과 같은 종류의 복제가 아니다

| | 원출처가 주는 것 | 우리가 만드는 것 | 페이지 단위 정보 이득 |
|---|---|---|---|
| **편의점 상세** | 소진공 상가정보의 상호·주소·업종 | 같은 값을 다시 표시 + 템플릿 문장 | **0** — 원출처에 그대로 있다 |
| **매물 상세** | 국토부의 시군구·월 단위 **raw 신고 목록** | 단지별 12개월 시세 추이, 평형별 분포, 층 프리미엄, 또래 대비 위치 | **있다** — 원출처에 이 형태로 존재하지 않는다 |

정책이 금지하는 것은 *"combining multiple sources **without added benefit**"*이다. 매물 상세는 집계·변환이 실제 산출물을 만들므로 그 반대편에 있다. **따라서 매물을 생활 인프라와 같은 버킷에 넣어 축소 대상으로 삼으면 안 된다.**

#### 축소 — 생활 인프라 (D1)

> **생활 인프라 상세 577,427개(66%)는 애초에 독립 페이지여야 하는가?**

이들은 임장 판단을 돕는 **보조 데이터**이고, 그 역할을 하는 UI가 **이미 존재한다** — "주변 생활 인프라" 위젯(`nearby-infra.tsx`). 편의점 한 곳에 URL·title·JSON-LD·브레드크럼을 붙여 독립 문서로 발행할 제품상 이유가 없다. 리서치가 권장한 **"페이지가 아니라 기능으로 제공"**이 정확히 이것이다.

> `/urban/charger` 9.9만은 이 묶음에서 뺄 것 — `revalidate=60` + `fetchChargerStatus()`로 **실시간 상태 조회**라 이미 "기능" 형태이고, 원출처에 없는 값을 제공한다. 지우면 바람직한 것을 지운다.

#### 복원 — 매물 (D2)

**축소만으로는 간판이 바뀌지 않는다.** 매물 상세 274,340개는 `index,follow`로 살아 있는데(`app/(public)/apt/[id]/page.tsx:64,79`) 커밋 `29e6fdb` 이후 사이트맵에서는 **0개**다. 지금 상태는 양쪽에서 최악이다:

| | 크롤·심사에 보이나 | 우리가 선언하나 |
|---|---|---|
| 매물 27.4만 | ✅ 보인다(미러 분모에 계상) | ❌ 사이트맵에 없다 |
| 병원·어린이집 10.5만 | ✅ 보인다 | ✅ 사이트맵의 90% |

매물은 분모에는 들어가면서 정체성 선언에는 기여하지 않고, 병원·어린이집은 분모에도 있고 간판까지 차지한다. `29e6fdb`가 얻은 것은 GSC "제출됐지만 noindex" 경고 0건 하나뿐이다.

**남는 긴장 — 이것이 D2의 실질이다.** 두 목표가 충돌한다.

1. **간판을 부동산으로** → 매물을 사이트맵에 넣어야 한다. 종전 게이트(`PROPERTY_INDEXABLE` = `txCount12m > 0 AND saleLastAt not null`)로는 **123,763개**(2026-08-09 실측)
2. **규모를 승인 사례 자릿수로** → 확인된 승인 사례는 수십~수백 페이지에 **페이지마다 사람이 쓴 설명**

12만 개를 그대로 넣으면 간판은 확실히 부동산이 되지만 "수만 페이지를 자동 서사로 감싼 사이트"라는 성격은 그대로다.

**해소 방향: 게이트를 데이터 밀도로 올린다.** "거래 1건 이상"이 아니라 *시계열이 실제로 성립하는 단지* — 우리가 원출처보다 나은 것을 **실제로 만들어낼 수 있는** 단지만 색인·등재한다.

## 2. 새로 발견된 실제 결함 — 오라벨과 URL 3중 증식

재진단이 놓친 것이자, PR #271·#272가 잡은 표시 결함과 **정확히 같은 계열**인데 규모가 수십만인 것.

### 2.1 `getById`에 카테고리 필터가 없다 (직접 확인)

`lib/amenity/adapters/convenience.ts:75-89` (cafe·mart 동일):

```ts

    where: { id },          // ← industryCode 필터 없음

```

목록 쿼리(`:55` 부근 `where`)에는 `industryCode` 필터가 있는데 `getById`에는 없다. 결과: **임의의 Store 행 하나가 `/amenity/convenience/{id}`·`/amenity/mart/{id}`·`/amenity/cafe/{id}` 세 URL 모두에서 200을 내고, 각각 자기참조 canonical을 방출한다.** 카페 한 곳이 "— 편의점" 제목 + JSON-LD `ConvenienceStore` + 브레드크럼 '편의점'으로도 렌더된다.

정책 매핑: Replicated content(동일 콘텐츠 다중 URL) + Misrepresentative content(오라벨).

### 2.2 `infraHref('etc')`가 기타 업소를 편의점으로 링크한다 (직접 확인)

## 6. 하지 말 것

| 하지 말 것 | 이유 |
|---|---|
| **noindex로 축소하기** | 애드센스 심사는 자체 크롤 기반이라 noindex는 페이지를 심사에서 숨기지 못한다(A급 공식 문서). 7월 약국 noindex는 심사 관점 **무효였다**. 축소는 de-publish여야 한다. 반대로 "이미 noindex니까 안전하다"는 반론도 폐기 |
| **매물을 생활 인프라와 같은 축소 버킷에 넣기** | 편의점은 원출처를 다시 표시할 뿐이라 정보 이득이 0이지만, 매물 상세는 국토부 raw 신고를 단지별 시계열로 집계해 **원출처에 없는 산출물**을 만든다(§1.2). 축소 대상은 D1, 매물은 D2(복원)다 |
| **`isNarrativeIndexable` 색인 게이트를 제거하기** | core 4모듈은 데이터가 있을 때만 발화하므로 이 게이트는 사실상 **데이터 충족도 게이트**다. 없애면 데이터 없는 단지까지 색인돼 악화된다. 손댈 곳은 게이트가 아니라 **출력(템플릿 문장)**이고, 게이트는 오히려 밀도를 올려야 한다 |
| **자동 생성 템플릿 문장·수치 카드·FAQ를 더 붙이기** | 네 라운드 전부 이것이었고 전부 실패했다. 정책 언어로 "slight modifications through automated techniques" |
| **분모 축소 없이 AI 가이드·board 편수만 늘리기** | 세 번 실패한 노선. 단 "편수 늘리기 자체 금지"는 과한 단정 — 표면을 수천으로 줄이면 76편은 승인 사례 자릿수 구간에 들어온다 |
| **`/list`를 색인 개방하기** | `parseListParams`가 10개 파라미터 자유조합. 색인하면 `?region=` 양산을 훨씬 큰 규모로 재생산 |
| **amenity/urban 상세만 제거하고 `infraHref`를 그대로 두기** | 사이트 전역 "주변 생활 인프라"가 통째로 죽은 링크가 되어 계층 신호를 **악화**시킨다 |
| **`/about`에 모델명 "gpt-4.1" 못 박기** | `scripts/generate-guides.ts:21`이 `process.env.GUIDE_MODEL ?? 'gpt-4.1'` — env 변경 시 즉시 허위 표기 |
| **"시황 브리핑은 언어모델을 쓰지 않습니다" 부정 고지** | 검증 부담만 늘고 향후 한 줄이라도 쓰면 허위화. 긍정형으로 |
| **`lib/insights/*` 자동 서사와 LLM 생성물을 같은 문단에서 고지하기** | 전자는 규칙 기반 문자열 조립, 후자는 LLM. 섞으면 "상세 페이지도 AI가 쓴다"는 잘못된 인상 |
| **운영 사이트에 curl 버스트** | 방화벽 챌린지(403) 유발 전력 |
| **현 상태로 4차 신청** | 3차와 동일한 사이트 구성. 결과가 달라질 근거 0 |
