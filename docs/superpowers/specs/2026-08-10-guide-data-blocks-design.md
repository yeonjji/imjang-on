# 가이드 데이터 블록 — 본문 주장을 자체 데이터로 증명하기

작성 2026-08-10. 상록 가이드 28편 중 8편에 **우리만 산출 가능한 실측 데이터 블록**을 넣고,
동일 구조에서 오는 "AI 티"를 새 텍스트 없이 줄인다.

배경: `docs/adsense/2026-08-09-4th-application-plan.md` §4 P2 — 애드센스 3차 거절(`Low value content`) 대응.

---

## 1. 문제

### 1.1 실측 (2026-08-10 운영 DB)

| | 값 |
|---|---|
| 본문 길이 | 평균 **2,085자** (1,725~2,449) |
| `## 소제목` 개수 | **25편이 정확히 7개** (8개 2편, 10개 1편) |
| `## 핵심 요약`·`## 자주 묻는 질문`·`## 참고 자료` | **28/28 전부 보유** |
| 카테고리 | 7종 × **정확히 4편씩** |

균일성은 우연이 아니라 설계다. `lib/guide/generate.ts`의 `SYSTEM_PROMPT` 규칙 7·10·11·12가
`## 핵심 요약` / `## 자주 묻는 질문` / `## 더 알아보기` / `## 참고 자료` **네 앵커를 정확히 그 제목으로**
쓰도록 강제한다. 자유 소제목은 2~3개뿐이다.

### 1.2 진짜 문제는 균일성이 아니라 정보 이득 0

`realestate-read-transaction-price` 본문 실측:

> "같은 아파트 단지라도 **평형이 다르면 가격 차이가 큽니다.**"
> "같은 평형이라도 **층수가 높거나 전망이 좋으면 가격이 더 높게** 거래될 수 있습니다."

전부 맞는 말인데 **숫자가 하나도 없다.** 국토부 안내문과 다를 것이 없다.
페이지 단위 정보 이득이 0이고, 이것이 `Low value content`의 실체다.

## 2. 확정된 방침

| 논점 | 결정 | 근거 |
|---|---|---|
| 늘어나는 분량을 무엇으로 채우나 | **자체 데이터만.** 설명 문장은 현재 길이 유지 | LLM이 문장을 확장하면 실패한 4라운드("자동 생성 텍스트를 더 많이")의 5회차가 된다 |
| 구조 균일성 | **`## 자주 묻는 질문` 섹션 제거**(대상 8편) | 균일성을 줄이는 방법은 "더 쓰기"만이 아니라 "빼기"도 있다. 새 텍스트가 생기지 않는다 |
| 데이터 주입 방식 | **본문 자리표시자 + 렌더 시 분할 치환** | 주장 바로 다음 줄에 증거가 붙어야 한다. 정적 표는 수치가 낡아 PR #271·#272가 잡은 정확성 결함 계열이 된다 |
| 이미지(스크린샷) | **넣지 않는다** | 인터넷등기소·청약홈 화면은 남의 화면 복제라 정책상 replicated content 쪽에 가깝다. 자체 데이터 차트와 성격이 다르다 |

### 2.1 명시적으로 하지 않는 것

- **본문 문장을 새로 쓰거나 재생성하지 않는다.** 한 글자도.
- **`/faq` 독립 페이지와 공용 `Faq` 컴포넌트(20개 라우트)는 건드리지 않는다.** 제거 대상은 가이드 본문 안의 `## 자주 묻는 질문` 섹션뿐이다. 셋은 서로 다른 것이다.
- 대상 8편 외 20편은 코드 경로가 그대로다(자리표시자가 없으면 지금과 동일하게 렌더).

## 3. 아키텍처

### 3.1 본문 분할 렌더

본문에 `[[data:<블록키>]]`를 **한 줄로** 넣는다. 렌더 시 그 표식으로 본문을 잘라 마크다운 조각과
블록 컴포넌트를 번갈아 그린다.

```
app/(public)/guide/[slug]/_components/guide-body.tsx
  const parts = body.split(/^\[\[data:([a-z0-9-]+)\]\]$/m);
  // 짝수 인덱스 = 마크다운 조각, 홀수 = 블록키
```

remark 플러그인을 쓰지 않는다. 표식이 없으면 `parts.length === 1`이라 기존 경로와 동일하다.
미지의 블록키는 **아무것도 렌더하지 않는다**(오타로 페이지가 깨지지 않게).

### 3.2 블록의 두 계층

기존 `lib/transaction.ts`의 함수는 **전부 `propertyId`를 받는 단지별 조회**다. 가이드에 필요한
전국·지역 집계는 없다. 그래서 비용에 따라 두 갈래로 나눈다.

| 계층 | 데이터 | 조회 | 근거 |
|---|---|---|---|
| **가벼운 블록** | 레지스트리 (병원 79,772 · 어린이집 25,151 · 충전소 101,703) | **렌더 시 직접 조회** | 단순 `GROUP BY`. 가이드는 `revalidate=86_400`이라 하루 1회 |
| **무거운 블록** | 실거래 (`Transaction` **7.6M행**) | **ETL 사전계산 → 스냅샷 읽기** | 층 파싱·평형 구간·시계열. 박스가 2코어이고 가이드는 `generateStaticParams`가 비어 첫 요청이 cold 렌더라, 크롤러가 그 요청을 맞으면 타임아웃 위험 |

### 3.3 스냅샷 — 기존 모델 재사용, 마이그레이션 없음

`DashboardSnapshot { key String @id, payload Json, computedAt DateTime @updatedAt }`가 이미 있다.
홈 대시보드(시황 브리핑·인기지역)가 쓰는 바로 그 패턴을 따른다.

| 홈 (기존) | 가이드 (신규) |
|---|---|
| `lib/dashboard-snapshot.ts` (`writeHomeSnapshot`/`readHomeSnapshot`) | `lib/guide/data-snapshot.ts` (`writeGuideSnapshot`/`readGuideSnapshot`) |
| `scripts/dashboard/refresh-snapshot.ts` | `scripts/guide/refresh-data-snapshot.ts` |
| `deploy/run-etl.sh:11`, `.github/workflows/ingest-transactions-daily.yml:54` | **같은 두 곳에 한 줄 추가** |

페이지는 스냅샷을 **즉시 읽는다**. 요청 경로에서 7.6M 집계가 도는 일은 없다.

## 4. 블록 9종과 대상 가이드 8편

### 4.1 가벼운 블록 (렌더 시 조회)

| 블록키 | 대상 가이드(`dedupeKey`) | 내용 | 증명하는 본문 주장 |
|---|---|---|---|
| `hospital-by-type` | `medical-hospital-tiers` | 종별 개수·평균 의사수·일반병상 | "종별로 규모가 다르다" |
| `childcare-by-type` | `childcare-types-and-choosing` | 유형별 개수·평균 정원·충원율 | "유형마다 차이가 있다" |

### 4.2 무거운 블록 (스냅샷)

| 블록키 = 스냅샷키 | 대상 가이드 | 내용 | 증명하는 본문 주장 |
|---|---|---|---|
| `area-price` | `realestate-read-transaction-price`, `realestate-area-pyeong-explained` | 평형대별 전용면적당 단가 | "평형이 다르면 가격 차이가 크다" |
| `floor-premium` | `realestate-read-transaction-price` | 저·중·고층 단가 (표본 수 병기) | "층수가 높으면 더 비싸다" |
| `price-trend-24m` | `realestate-read-transaction-price` | 24개월 거래량·중위가 추이 | "최근 거래인지 과거 거래인지 봐야 한다" |
| `subway-premium` | `life-subway-access` | 역 도보권/비도보권 단가 차이 | "역세권은 값이 다르다" |
| `ltv-by-region` | `finance-ltv-dsr-mortgage-regulation` | 시도별 평균 실거래가 × 규제 비율 = 필요 자기자금 | "규제가 실제로 얼마를 뜻하는가" |

`area-price`는 두 가이드가 공유한다(스냅샷 1개, 렌더 2곳).

**`subway-premium`과 `ltv-by-region`이 가장 강하다.** 원출처 어디에도 없고, 지하철 좌표·대출 규제와
실거래를 결합해야만 나온다 — 정책이 요구하는 "combining multiple sources **with** added benefit"에 해당한다.

### 4.3 대상에서 뺀 20편

우리 데이터로 뒷받침되지 않는 편(등기부등본, 학교알리미 사용법, 보육료 지원 등)에는 넣지 않는다.
**억지로 붙이면 그 자체가 near-duplicate 블록 양산이 된다.**

## 5. 본문 수정

일회성 스크립트로 처리한다. 8편을 어드민에서 손으로 고치면 실수가 난다.

```
scripts/guide/insert-data-blocks.ts
  --dry-run   diff만 출력(기본)
  --apply     실제 반영
```

동작:
1. `dedupeKey`로 대상 8편 조회
2. `## 자주 묻는 질문` 섹션 제거 — 해당 헤딩부터 **다음 `## `까지**
3. `[[data:<키>]]` 삽입. 위치는 **`(dedupeKey, 블록키) → 앵커 소제목` 표를 스크립트에 상수로 박고**,
   그 소제목 섹션의 끝(다음 `## ` 직전)에 넣는다. 표의 실제 값은 §4의 "증명하는 본문 주장"이
   어느 소제목 아래 있는지 확인해 구현 시 확정하고, `--dry-run` diff로 검토한 뒤 반영한다.
   앵커 소제목을 못 찾으면 **그 편은 건너뛰고 경고를 출력한다**(임의 위치에 넣지 않는다).
4. **멱등** — 이미 표식이 있으면 건너뛴다. 재실행해도 중복 삽입되지 않는다

되돌리기는 `app/admin/guides/[id]/guide-editor.tsx`로 가능하다.

## 6. 작성일·편집자 UI

`app/(public)/guide/[slug]/page.tsx:46`이 `published`를 계산해 **JSON-LD에만 쓰고 화면에는 안 쓴다.**
board 상세와 같은 형태로 올린다.

```
임장ON 가이드 · 금융                  ← 기존
2026년 6월 29일 · 임장ON 편집자        ← 신규
[자동 생성 고지]                       ← PR #277에서 이미 추가됨
```

표기는 "작성"이 아니라 **"편집"**으로 한다 — PR #277이 JSON-LD `author`를 `Organization`으로 바꿨고,
본문이 언어모델 초안 + 운영자 검수라는 사실과 어긋나지 않아야 한다.

## 7. 오류 처리

| 상황 | 동작 |
|---|---|
| 스냅샷 없음 / 조회 실패 | 블록이 `null` 반환 → **그 자리만 빈다.** 본문은 그대로 읽힌다 |
| 미지의 블록키 | 아무것도 렌더하지 않는다 |
| 스냅샷이 낡음 | **숨기지 않는다.** 블록 하단 기준일(`SourceCaption` 재사용)에 그대로 드러난다 |
| 표본 부족 | 블록이 `null`. 예: 층 프리미엄은 표본 하한 미달 시 미표시 |

모든 블록은 하단에 데이터 기준일과 출처를 단다 — `PRODUCT.md`의 "모든 수치에 출처 표기" 원칙.

## 8. 테스트

**유닛**
- 본문 분할: 표식 없음 / 1개 / 여러 개 / 미지 키 / 표식이 코드블록 안에 있는 경우
- 집계 함수 9종: 빈 데이터에서 `null`, 정상 데이터에서 기대 형태
- `insert-data-blocks.ts` 멱등성: 두 번 실행해도 결과 동일
- FAQ 제거: 다음 `## `까지만 지우고 그 뒤는 보존

**e2e**
- 대상 가이드: 블록이 렌더되고 기준일이 보인다
- 대상 가이드: `자주 묻는 질문`이 없다
- **비대상 가이드: 지금과 동일하게 렌더된다** (회귀 가드)
- 날짜·편집자 노출

**검증 순서**: `pnpm lint` → `typecheck` → `test:unit` → `build` → `seed:e2e` → Playwright 전량.
UI 문구가 바뀌므로 e2e 생략 금지.
