## 2. 데이터 모델

```prisma
/// 초등학교 통학구역(학구도). 반기 배포(3·9월) 파일을 통째로 교체 적재한다.
model SchoolZone {
  hakgudoId String  @id @db.VarChar(19)   // HAKGUDO_ID
  name      String  @db.VarChar(120)      // HAKGUDO_NM
  kind      String  @db.VarChar(12)       // 'general' | 'shared' | 'shared_oneway' | 'wide' (이름에서 분류)
  eduName   String? @db.VarChar(60)       // EDU_NM 교육지원청명 (확인 안내 문구에 사용)
  baseDate  DateTime @db.Date             // BASE_DT
  geom      Unsupported("geometry(MultiPolygon,4326)")
  schools   SchoolZoneSchool[]

  @@index([geom], type: Gist)
}

model SchoolZoneSchool {
  hakgudoId  String  @db.VarChar(19)
  schId      String  @db.VarChar(19)      // SCHID (학구도 체계)
  schoolName String  @db.VarChar(60)      // SCHNM (원문 그대로, "(휴교)" 포함)
  eduOffice  String  @db.VarChar(60)      // 시·도 교육청명(별칭 정규화 후). School.eduOffice와 매칭
  /// 우리 School 매칭 결과. 확실할 때만 채운다(링크용). null이면 이름만 표시.
  schoolId   BigInt?
  /// 광역통학구역의 기본 학교(학구명 접두어와 일치). 일반·공동은 모두 true.
  isPrimary  Boolean
  zone       SchoolZone @relation(fields: [hakgudoId], references: [hakgudoId], onDelete: Cascade)

  @@id([hakgudoId, schId])
}
```

- `@@index([geom], type: Gist)`가 Prisma에서 Unsupported 타입에 안 되면 마이그레이션 SQL로 직접 만든다.

## 3. 적재 (반기 1회, 수동 실행)

`scripts/ingest/school-zone/` — `pnpm ingest:school-zone [--zone-zip=… --link-csv=…]`

1. **다운로드:** 인자가 없으면 data.go.kr에서 두 파일을 직접 받는다(§1의 두 단계 요청).
2. **SHP 읽기:** zip을 메모리에서 풀고, 확장자로 `.shp`/`.dbf`를 고른다(파일명이 CP949라 이름으로 찾지 않음). DBF는 EUC-KR로 디코드한다.
3. **좌표 변환은 DB에서 한다:** `ST_Multi(ST_MakeValid(ST_Transform(ST_SetSRID(ST_GeomFromGeoJSON($1), 5186), 4326)))`
4. **학교 매칭:** 학교명 + 시·도 교육청(별칭: 광주광역시교육청 → 전남광주통합특별시교육청(광주), 전라남도교육청 → (전남))으로 찾는다.
   - 1곳이면 학구에서 10km 이내일 때 채택한다.
   - 여러 곳이면 학구에서 3km 이내인 학교가 정확히 1곳일 때만 채택한다.
   - 그 외에는 null로 둔다.
5. **트랜잭션 교체:** 두 테이블을 지우고 다시 넣는다. 적재 후 행 수가 이전의 90% 미만이면 롤백한다(빈 파일 사고 방지).
6. `IngestionRun`(source `school-zone`, targetKey = 기준일)에 기록한다.

**새 의존성(승인 필요):** `shapefile`(SHP/DBF 파서)과 `fflate`(zip 해제). 둘 다 순수 JS다. 박스에 GDAL이 없으므로 필요하다.

## 4. 화면 (모양은 UI 시안에서 확정)

- **위치:** 아파트 상세 `NearbySubway` 바로 위. id는 `school-zone`. 사이드바 바로가기 "배정 초등학교".
- **조회:** 페이지 렌더 시 `ST_Contains(z.geom, p.location::geometry)` 한 번(GiST 인덱스). 그다음 학구의 학교를 조회한다. 외부 API 호출은 없다.
- **숨김:** 좌표가 없거나 포함된 학구가 없으면 섹션을 숨긴다.

| 유형 | 표시 |
|---|---|
| 일반 | "단지 대표 위치 기준 통학구역: **○○초등학교**" + 직선거리 + 학교 상세 링크(매칭 시) |
| 공동 | "공동통학구역 — 여러 학교가 함께 지정된 구역입니다" + 학교 목록(각 거리·링크) |
| 공동(일방) | 공동과 같이 표시하고 "(일방)"을 붙인다. 방향 해석은 하지 않는다 |
| 광역 | 기본 학교를 일반처럼 표시 + "광역통학구역으로 함께 지정된 학교: △△초(○km)" |

- **모든 유형 공통 안내:** "통학구역은 교육청이 조정할 수 있고 동·호수에 따라 다를 수 있습니다. 실제 배정 학교는 {교육지원청명}에 확인하세요."
- **출처:** "재단법인 한국지방교육행정연구재단 학구도 · 기준일 2025-09-22". 거리는 "직선거리(임장ON 계산)"로 표시한다.
- **해석 금지:** 학교 평가나 "배정됩니다" 같은 단정 문구는 쓰지 않는다.

## 5. 테스트

- 유닛: 학구 유형 분류(이름 → kind), 광역 기본 학교 식별, 교육청 별칭, 매칭 규칙(1곳/여러 곳/거리 초과)
- 통합: 적재 트랜잭션(교체·90% 가드), 아파트 좌표 → 학구 조회(포함·미포함)
- 렌더링: 유형별 문구, 매칭 없는 학교는 링크 없음, 공통 안내·기준일
- e2e: 시드에 학구 폴리곤 1개 + 학교 1곳, 래미안서초 페이지에 섹션 렌더
- 실데이터 QA: 일반·공동·공동(일방)·광역 각 1곳의 페이지를 읽기전용 터널로 확인
