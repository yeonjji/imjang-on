# 학교찾기 독립 페이지 + 생활인프라 메뉴 설계

작성일: 2026-05-27
상태: 설계 확정 대기 (사용자 리뷰 중)

## 1. 배경 & 목표

수집 완료된 생활인프라 데이터(학교·공원·전통시장·편의시설/Store·EV충전소) 중 **학교(12,560건)**를 첫 대상으로, 독립된 목록·상세 페이지를 구축한다. 동시에 향후 생활인프라 5종을 담을 **메뉴/정보구조(IA)**를 확정한다.

부동산 단지 상세에 생활인프라를 통합하는 작업(역방향: 단지→주변 인프라)은 **이번 범위 밖**이며, 학교 독립 페이지를 먼저 완성한 뒤 별도로 진행한다.

핵심 차별점: 학교 상세에서 **그 학교 주변 아파트 실거래가**를 함께 보여줘(학교→아파트 역방향 연결) 플랫폼의 "이 위치에 살면 어떤 생활인가"라는 컨셉을 구현한다.

## 2. 범위

### 포함
- 생활인프라 허브 페이지(`/life`)와 상단 메뉴/푸터 IA
- 학교 목록(시도 허브 → 시군구 목록+필터) 페이지
- 학교 상세 페이지(기본정보 + 네이버 지도 + 주변 아파트 + 주변 인프라)
- `School.sigunguCode` 추가 및 주소 기반 백필
- `lib/amenity.ts`에 공원·학교 근접 조회 함수 추가

### 제외 (후속 작업)
- 단지 상세 페이지의 생활인프라 통합
- 공원·마트·편의·충전소의 독립 페이지 (메뉴엔 Soon 자리만)
- **병원·약국 카테고리** — 현재 Store 의료 데이터를 쓰지 않고, 추후 더 나은 데이터를 수집해 별도 작업으로 진행. 메뉴엔 Soon 표시만.

## 3. 정보구조(IA) & 메뉴

상단 네비게이션:
```
임장온   홈   실거래가   생활인프라   청약(Soon)        [검색]
```
- **생활인프라**는 단일 링크로 허브 페이지(`/life`)로 이동 (드롭다운 아님)
- 애드센스 관점 채택 이유: 허브가 색인되는 콘텐츠 페이지가 되어 광고 지면·페이지뷰 1단계 추가, 상단은 깔끔(모바일 친화), 푸터 카테고리 링크로 크롤러 내부링크 확보.

`/life` 허브 페이지: 5개 카테고리 카드
| 카테고리 | 데이터 소스 | 상태 |
|---|---|---|
| 🏫 학교 | School | ✅ 활성 (`/school`) |
| 🏥 병원·약국 | (추후 신규 수집) | Soon |
| 🛒 마트·편의 | Store(편의점·슈퍼·대형마트·카페) + TraditionalMarket | Soon |
| 🌳 공원 | Park | Soon |
| ⚡ 충전소 | EvCharger (주차장 미수집) | Soon |

- Soon 카테고리는 기존 `SoonModal` 또는 허브 카드의 "준비중" 상태로 처리.
- 카테고리→데이터 매핑은 코드 상수로 정의(업종코드→카테고리). DB 스키마에 카테고리 개념을 넣지 않는다.
- 푸터: 5개 카테고리 텍스트 링크 노출(활성은 링크, Soon은 비활성 또는 허브로).

## 4. 라우팅

기존 `/region` 패턴과 일치, 모두 계층형으로 breadcrumb·canonical에 유리.
```
/life                          생활인프라 허브 (ISR 24h)
/school                        지역 선택 허브 — 시도별 섹션 + 시군구 링크 그리드 (ISR 24h)
/school/[sigunguCode]          시군구 학교 목록 + 필터 (ISR 6h)
/school/[sigunguCode]/[id]     학교 상세 (ISR 24h)
```
- `sigunguCode`는 Region의 5자리 시군구 코드(기존 `/region/[code]`와 동일 체계).
- 단일 세그먼트 충돌 없음(`[sigunguCode]` 다음 깊이에 `[id]`).
- **시도/시군구 2단계 드릴다운을 별도 라우트 없이** 처리: `/school` 한 페이지가 시도별로 묶인 시군구 링크를 모두 보여주고, 각 시군구가 `/school/[sigunguCode]`로 이동. (252개 시군구를 시도 섹션으로 나열 — 한 페이지로 충분, 추가 `/school/[sido]` 라우트 불필요)

## 5. 데이터 준비: School → 시군구 매핑

현재 `School`에는 `region`(시도 문자열)만 있고 `sigunguCode`가 없어 드릴다운이 불가능하다.

- 스키마: `School`에 `sigunguCode String? @db.VarChar(5)` + `@@index([sigunguCode, schoolKind])` 추가. Prisma 마이그레이션 생성.
- 백필: 1회성 스크립트(`scripts/ingest/amenities/school-region-backfill.ts` 등)로 각 학교의 **도로명주소를 파싱**해 시도+시군구를 추출하고 `Region`(level=시군구)과 매칭해 `sigunguCode`를 채운다.
  - 매칭 키: `Region.sido` + `Region.sigungu` 문자열. 도로명주소 앞부분이 "시도 시군구 …" 형태(예: "서울특별시 강남구 …")라 매칭률 높음.
  - 광역시 자치구, 도-시-군, 세종시 등 경계 케이스 처리. 매칭 실패 행은 로깅하고 `sigunguCode=NULL` 유지.
- 검증: 백필 후 `sigunguCode IS NULL` 비율을 확인(목표 95%+ 매칭). 좌표 기반 보정은 Region에 폴리곤이 없어 사용하지 않는다.

## 6. 학교 목록 페이지

### `/school` (지역 선택 허브)
- 시도별 섹션으로 그 시도의 시군구 링크를 그리드로 나열(서울 › 강남구/서초구/…, 경기 › …). 각 시군구 링크 → `/school/[sigunguCode]`.
- 시군구 칩에 학교 수를 함께 표시하면 회유율↑(쿼리 1회로 시군구별 카운트 집계 가능).
- 별도 `/school/[sido]` 라우트는 만들지 않는다.

### `/school/[sigunguCode]` (시군구 목록 + 필터)
목업: `html/school-list.html`
- breadcrumb: 홈 › 생활인프라 › 학교찾기 › {시도} › {시군구}
- 헤더 카드: 지역명, 학교급별 카운트 칩, 지역 변경 버튼
- 좌측 280px 필터 패널(기존 `/list` 필터 컴포넌트 패턴 재사용):
  - 학교명 검색(부분 일치, `pg_trgm` 활용 가능)
  - 학교급: 전체/초등학교/중학교/고등학교/특수 (`schoolKind`)
  - 설립유형: 전체/국공립/사립 (`foundType`)
  - 남녀공학: 전체/남/여/공학 (`coeduType`)
  - 광고 영역
- 우측 목록: 학교 카드(아이콘, 이름, 태그[학교급·설립·남녀공학], 주소) + 페이지네이션
- 필터는 쿼리스트링으로(`?kind=&found=&coedu=&q=&page=`). 목록 자체는 ISR + 클라이언트 필터 토글 또는 SSR 쿼리. 기본은 ISR 페이지에 필터 쿼리.
- **목록 카드에 "주변 아파트 N단지" 티저는 넣지 않는다.** 학교마다 PostGIS 반경 카운트가 필요해 목록 쿼리가 무거워짐. 주변 아파트는 상세에서만 보여준다. (목업의 티저 문구는 제거)

## 7. 학교 상세 페이지

목업: `html/school-detail.html`, 라우트 `/school/[sigunguCode]/[id]`
- Hero: 학교명 + 태그(학교급/설립/남녀공학) + 주소·전화·홈페이지
- 2컬럼(본문 + 우측 사이드바), 기존 apt 상세 레이아웃 패턴 재사용:
  - 본문:
    1. **학교 정보** — 학교급, 설립유형, 남녀공학, 관할 교육청(`eduOffice`), 전화, 지역
    2. **위치** — 네이버 지도 위젯(아래 8절)
    3. **주변 아파트 실거래가** — 반경 1km 내 Property를 PostGIS로 조회, 거리순. 단지명·거리·준공·세대수·매매/전세 시세, `/apt/[id]` 링크. "더보기".
    4. **주변 생활 인프라** — 탭: 공원 / 마트·편의 / 충전소 (병원·약국 제외). 각 거리순 상위 N개. 메뉴 카테고리와 동일한 그룹 사용.
  - 우측 사이드바: 목차(앵커) + 같은 시군구 다른 학교 + 광고
- 주변 아파트/인프라는 학교 `location` 기준 PostGIS `ST_DWithin`/`ST_Distance` 사용. 학교 지오코딩 채움률 99.6%(12,515/12,560).

## 8. 모바일 / 반응형 (모바일 우선)

한국 부동산 트래픽 대부분이 모바일 → 모바일을 1차 화면으로 설계한다. (현재 목업은 기본 브레이크포인트만 있고 목록 필터를 숨기는 등 미완 상태이므로 아래 기준으로 보완)

- **네비게이션**: 데스크톱은 가로 메뉴, 모바일은 햄버거 → 드로어/풀스크린 메뉴(홈·실거래가·생활인프라·청약). 현재 `nav`가 `md` 이하에서 메뉴를 감추므로 모바일 메뉴 구현 필요.
- **목록 필터(중요)**: 데스크톱 좌측 280px 고정 사이드바. **모바일에서 필터를 숨기지 않는다** — 상단 "필터" 버튼 → 기존 `MobileFilterSheet`(`components/ui/bottom-sheet.tsx`) 재사용. 적용된 필터는 상단에 칩으로 노출.
- **학교 카드**: 모바일 1열, 이름·태그 줄바꿈 허용, 우측 메타는 하단으로 스택. 터치 타깃 ≥ 44px.
- **상세 2컬럼 → 1컬럼**: 우측 사이드바(목차·다른 학교·광고)는 본문 아래로 스택. 목차는 모바일에선 생략하거나 상단 가로 스크롤 앵커 칩으로.
- **지도**: 모바일 높이 축소(예 220px), 가로 100%.
- **필터 칩 그룹**: 가로 스크롤 또는 wrap 처리.
- **/life 허브 카드**: 데스크톱 5열 → 모바일 2열 그리드.
- **광고(애드센스)**: 데스크톱 사이드바 광고는 모바일에선 콘텐츠 사이 인라인 반응형 단위로 전환. 모바일 앵커/전면 광고는 정책·UX 고려해 신중히.
- Tailwind 브레이크포인트는 기존 컴포넌트와 `md` 기준으로 통일.

## 9. 지도: 네이버

- 네이버 지도로 학교 위치 표시. **NCP(네이버 클라우드 플랫폼) Maps API 클라이언트 ID** 필요 → 환경변수 추가(`lib/env.ts`), Vercel 환경변수 등록.
- 좌표는 기존 카카오 지오코딩 결과(WGS84)를 그대로 사용.
- 정적 지도 vs 동적 JS 지도: 단지 상세의 기존 지도 위젯 방식을 확인해 일관성 있게 결정(구현 계획 단계에서 확정).

- `lib/amenity.ts`: 현재 EV충전소·전통시장·Store 근접 조회만 존재. **공원(`getNearbyParks`)·학교 단건 조회/근접** 함수 추가. 상세 탭 구성(공원/마트·편의/충전소)에 맞춰 묶음 조회 함수 정리.
