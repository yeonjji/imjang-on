# 동네 실거래 목록 — 홈 히어로 패널 + 상세 섹션 설계

**상태:** 설계 확정 대기 · 구현 착수 전
**범위:** 홈(`/`) 히어로 오른쪽 패널, 실거래가 상세(`/apt/[id]`·`/villa/[id]`·`/officetel/[id]`) 섹션 하나.

## 1. 무엇을 만드나

한 동네의 최근 실거래를 거래 단위로 나열하는 목록을 두 곳에 넣는다.

- **홈** — 히어로 오른쪽에 지역 선택(시도·시군구·읍면동) + 목록
- **상세** — 그 매물이 속한 동의 목록. 선택 없이 고정

두 화면은 **조회 함수 하나와 행 렌더 컴포넌트 하나**를 공유한다.

## 2. 기존 「주변 단지 실거래가 비교」와 다른 점

상세 페이지 하단에 이미 `NearbyPriceComparison`이 있다. 중복이 아니다.

| | 기존 「주변 단지 실거래가 비교」 | 신규 「이 동네 최근 거래」 |
|---|---|---|
| 단위 | **단지** (Property 1행) | **거래** (Transaction 1행) |
| 범위 | 반경 2km (`ST_DWithin`) | 같은 읍면동 |
| 정렬 | 거리순 | 계약일 최신순 |
| 내용 | 단지별 최신 매매/전세/월세 요약 | 거래 건별 계약일·면적·가격·층 |

**긴장 요소:** 둘 다 "주변"이라 멀리 떨어져 있으면 어색할 수 있다. 신규 섹션은 「이 단지 최근 실거래 내역」 바로 아래에 두되(§5), 배포 후 화면을 보고 위치를 조정할 수 있게 열어 둔다.

## 3. 데이터 — 실측으로 확인한 제약

### 3.1 `Transaction.regionCode`는 시군구 코드다

법정동 코드가 아니다. 99.7%가 시군구 5자리 + `00000`이고 distinct 값이 258개(시군구 수 262와 일치)다.

```
regionCode  5219000000   sigunguCode  52190   umd  도통동
```

**동은 `umd`라는 이름 문자열로만 존재한다**(채움률 100%). 코드가 없으므로 동 단위 조회는 `(sigunguCode, umd)` 쌍으로 한다.

### 3.2 드롭다운을 `Region` 테이블로 만들면 안 된다

`Transaction`의 (시군구, 동) 조합 5,285개 중 `Region` level 3에 이름이 일치하는 건 2,100개(40%)뿐이다. 원인이 둘이다.

**(a) 지방은 `읍면 + 리`가 통째로 들어온다** — 거래 건수의 10.5%
```
12130  "돌산읍 우두리"      Region level3은 "화양면, 남면, 화정면"
12130  "소라면 덕양리"      → 리 단위라 면 목록과 매칭 불가
```

**(b) `Region` 쪽 결손·표기 차이** — 거래 건수의 22.0%. `Region` level 3에 법정동과 행정동(`상도동` / `상도1동`)이 섞여 있고 일부 법정동이 없다.

`Region`으로 옵션을 만들면 **선택해도 0건인 동이 대량 발생**하고, 거래가 있는 동의 상당수는 목록에 아예 안 뜬다.

→ **옵션을 실거래 데이터 자체에서 만든다.** 모든 선택지가 구조적으로 결과를 갖는다.

### 3.3 잘못된 시군구↔동 쌍은 극소량이고 임계값으로 걸러진다

```
봉천동     관악구 38,442건  ·  동작구      1건   ← 오염
사당동     동작구 18,792건  ·  관악구      3건   ← 오염
청량리동   동대문구 3,435건 ·  성북구      2건   ← 오염
신당동     중구 12,356 · 대구 달서구 754 · 천안 서북구 522  ← 정상(실제 동명이인)
```

오염은 1~3건 수준이다. **옵션을 "거래 8건 이상인 동"으로 만들면 전부 사라진다.**

### 3.4 거래량 분포 — 기간 제한을 두지 않는 이유

최근 3개월 기준 (시군구, 동) 조합 4,117개의 분포:

```
p10   1건
중앙값 20건
p90   293건
8건 이상  64.2%
```

3개월로 끊으면 **36%의 동에서 목록이 8칸을 못 채운다.** 기간 제한 없이 "최신 N건"을 가져오면 어디서든 채워진다.

### 3.5 성능 — 인덱스가 이미 있다

`[regionCode, contractDate desc]`로 시군구 안에서 최신순으로 걷다가 `umd`가 맞는 걸 N건 채우면 멈춘다. 가장 뜸한 동에서도 빠르다.

```
강남구 율현동(강남구 거래의 0.4%) 최신 8건
  Index Scan using Transaction_regionCode_contractDate_idx
  Rows Removed by Filter: 3727
  Execution Time: 4.2ms
```

## 4. 공통 계층

### 4.1 조회

```ts
// lib/transaction/dong.ts (신규)
export interface DongTransaction {
  contractDate: string;      // 'YYYY-MM-DD'
  propertyId: string;
  propertyName: string;
  propertyType: PropertyType;
  exclusiveArea: number;     // ㎡
  floor: number | null;
  dealType: DealType;        // SALE | JEONSE | WOLSE
  dealAmount: number | null; // 만원, SALE
  deposit: number | null;    // 만원, JEONSE·WOLSE
  monthlyRent: number | null;// 만원, WOLSE
}

export async function getDongTransactions(opts: {
  sigunguCode: string;
  umd: string;
  dealType?: DealType;        // 미지정 = 전체
  propertyType?: PropertyType; // 미지정 = 전체
  limit?: number;             // 기본 8
}): Promise<DongTransaction[]>;
```

`regionCode = sigunguCode + '00000'`으로 인덱스를 태운다.

### 4.2 행 렌더

```tsx
// components/ui/dong-transaction-list.tsx (신규)
<DongTransactionList items={DongTransaction[]} />
```

한 행의 구성:

```
09.09   올림픽훼밀리타운   [전세]  9억 5,000   11층
        84㎡
```

- 계약일은 `MM.DD`
- 단지명은 상세 페이지로 링크, 넘치면 말줄임
- 거래유형은 배지 — 매매/전세/월세
- 금액은 기존 `formatBillion` 사용. 월세는 `보증금/월세`
- **상승·하락 색은 쓰지 않는다.** 이 목록은 변화가 아니라 사실의 나열이다

빈 배열이면 `null`을 반환한다. 「거래 없음」 같은 자리표시자를 두지 않는다.

## 5. 상세 페이지 섹션

**위치:** `UnifiedTransactionTable`(「이 단지 최근 실거래 내역」) 바로 아래.

```tsx
<DongTransactionSection
  id="dong"
  sigunguCode={property.sigunguCode}
  umd={umdOfProperty(property.address)}   // §7.1
  propertyType={property.propertyType}
  excludePropertyId={property.id}
/>
```

- 제목: `{동 이름} 다른 단지 최근 거래`
- 부제: `같은 동네 {유형}의 최근 거래 내역입니다`
- **그 매물과 같은 `propertyType`만** 보여준다. 비교가 목적이라서다
- **자기 단지는 제외한다.** 바로 위 섹션이 이미 그 단지의 거래를 보여준다
- 거래유형 탭(전체·매매·전세·월세). 기본 전체
- 8건. 「{동} 거래 전체 보기 →」로 `/list`에 연결
- 서버 조회. 클라이언트 상호작용은 탭뿐
- 데이터가 없으면 섹션 전체가 사라진다
- 사이드바 목차에 항목 추가 — 본문 렌더 여부와 같은 판정을 쓴다

빌라·오피스텔 상세도 같은 배선을 넣는다. 세 페이지가 갈리지 않게 한다.

## 6. 홈 패널

### 6.1 레이아웃

히어로 그리드 비율을 바꾼다.

```
변경 전  md:grid-cols-[1.05fr_0.95fr]   (거의 50:50)
변경 후  md:grid-cols-[1.65fr_1fr]      (약 62:38)
```

오른쪽이 왼쪽보다 확실히 좁아진다. 목업의 비율과 같다.

**아이콘 8칸(`TypeIconGrid`)은 오른쪽에서 왼쪽 아래(CTA 버튼 밑)로 옮긴다.** 왼쪽이 넓어져 아이콘이 오히려 커진다.

```
┌──────────────────────────────┬─────────────────┐
│ 📍 실거래가·생활권 정보 통합    │ 동네별 최근 실거래가 │
│ 어디든, 임장ON에서…           │ 관심 지역의 거래 내역 │
│ [검색창]                      │ [시도][시군구][읍면동]│
│ 인기 지역 #송파구 #강서구 …     │ [전체][매매][전세][월세]│
│ [실거래가 찾기] [청약 일정]     │ ───────────────│
│ 🏢 🏬 🏘️ 🏫                   │ 09.09 올림픽훼밀리…│
│ 🌳 🏪 ⚡ 🏥                    │ …  8건           │
│                              │ 문정동 더 보기 → │
└──────────────────────────────┴─────────────────┘
```

**모바일**(`md` 미만)에서는 세로로 쌓인다. 패널이 히어로 아래에 오고 폭은 100%다.

### 6.2 지역 선택

3단 캐스케이드. **시도·시군구는 기존 `/api/regions`를 그대로 쓴다**(이미 5개 화면이 쓰는 검증된 패턴). 읍면동만 새로 만든다.

```
GET /api/regions?sido=서울              → 시군구 목록 (기존)
GET /api/dongs?sigunguCode=11680        → 읍면동 목록 (신규)
GET /api/dong-transactions?sigunguCode=11680&umd=역삼동&dealType=SALE  (신규)
```

`gu=1`을 쓴다 — 실거래는 일반구 단위로 적재되므로 `/list`와 같은 기준이어야 한다.

### 6.3 읍면동 옵션 스냅샷

`/api/dongs`는 **ETL 사전계산 스냅샷**을 읽는다. 요청 경로에서 7.9M행에 `DISTINCT`를 돌리지 않는다. 이 저장소가 홈 브리핑·인기지역에 이미 쓰는 방식이다.

```
DongOption { sigunguCode, umd, txCount }
   조건: 거래 8건 이상 (§3.3 오염 제거)
   정렬: txCount desc
   규모: 약 4,000행
```

일 1회 ETL에서 갱신한다. 동 목록은 거의 변하지 않으므로 하루 지연은 무해하다.

### 6.4 첫 화면

홈은 ISR(`revalidate = 900`)이다. 서버가 **인기 지역 1위 시군구의 거래 최다 동**을 골라 목록까지 프리렌더한다. 홈이 이미 `popularRegions`를 스냅샷에서 읽고 있으므로 추가 조회가 없다.

드롭다운을 바꾸면 그때부터 클라이언트가 `/api/dong-transactions`를 호출한다. 선택은 **URL에 반영하지 않는다** — 홈 URL을 오염시키지 않고 색인에도 영향이 없다.

### 6.5 필터

- **거래유형 탭** — 전체·매매·전세·월세. 기본 전체
- **건물유형 select는 두지 않는다.** 홈은 "이 동네 전반"이 목적이라 유형을 섞어 보여준다. 컨트롤이 하나 줄어 좁은 패널에 여유가 생긴다

### 6.6 라벨

**"동"이 아니라 "읍면동"으로 쓴다.** 지방 10.5%에서 `돌산읍 우두리` 같은 리 단위 표기가 섞이는데(§3.2a), "동"이라고 하면 어긋나 보인다. 국토부가 주는 표기를 그대로 두고 라벨을 맞춘다.

## 7. 확정한 구현 세부

### 7.1 `Property`에서 `umd` 얻기 — 주소의 마지막 토큰을 뗀다

`Property`에 `umd` 컬럼은 **없다.** 대신 `Property.address`가 `umd + ' ' + jibun`으로 조립된다(`lib/property.ts:93` 주석이 명시). 따라서 **마지막 토큰만 떼면 `umd`가 그대로 나온다.**

```ts
// lib/transaction/dong.ts
export function umdOfProperty(address: string): string {
  return address.replace(/\s+[^ ]+$/, '');
}
```

```
"범어동 2272"        → "범어동"
"고촌읍 신곡리 100"   → "고촌읍 신곡리"     ← 실거래 umd와 같은 형식
"수성동1가 15"       → "수성동1가"
```

**실측: 표본 3,000건 중 2,970건(99.0%) 일치.** 추가 조회가 필요 없다.

불일치 30건(1.0%)은 한 매물의 거래가 여러 `umd`에 걸친 경우다(`송파동 117-3` ↔ 거래 `삼전동`). 이 경우 주소 쪽을 정본으로 본다 — 매물이 어느 동에 있는지는 주소가 말한다.

**기존 `dongOfAddress()`(`scripts/ingest/apt-complex/match.ts`)를 쓰면 안 된다.** 그 함수는 **앞** 토큰을 뽑아 `고촌읍 신곡리 100` → `고촌읍`을 반환하는데, 실거래 `umd`는 `고촌읍 신곡리`라 지방에서 어긋난다. 용도가 다른 함수다.

### 7.2 자기 단지 제외의 부작용

`excludePropertyId`로 거르면 8건을 못 채울 수 있다. `LIMIT`를 넉넉히 잡고(16) 제외한 뒤 앞 8건을 쓴다.

### 7.3 홈 첫 화면의 동 선택

`PopularRegion`은 `{ sigunguCode, sido, sigungu }`다(동이 없다). 인기 1위 시군구를 받아 **읍면동 스냅샷에서 그 시군구의 `txCount` 최상위 동**을 고른다. 스냅샷이 이미 `txCount desc`로 정렬돼 있어 추가 계산이 없다.

## 8. 검증

- **순수 함수 테스트** — 금액 표기(매매/전세/월세), `MM.DD` 변환, 빈 배열 처리
- **SSR 계약** — `renderToStaticMarkup`으로 0건·1건·8건, 월세 혼합, 긴 단지명을 렌더해 자리표시자가 새어나오지 않는지 확인. 이 저장소에는 `@testing-library`가 없다
- **쿼리 테스트** — `(sigunguCode, umd)`로 정확히 그 동만 나오는지, 최신순인지, `propertyType`·`dealType` 필터가 듣는지
- **홈 회귀** — 히어로 레이아웃 변경이 기존 요소(검색·인기지역·CTA·아이콘)를 깨지 않는지. `tests/e2e`의 홈 스펙 확인
- **배포 후 실측** — 드롭다운 옵션 중 0건이 나오는 조합이 실제로 없는지, 리 단위 표기가 얼마나 노출되는지, 홈 응답 시간 변화

## 9. 배포

**애드센스 심사 중이다.** main에 머지하면 CI 통과 후 자동 배포되고 `web` 컨테이너가 재생성된다.

- 브랜치에서 작업한다
- **두 화면이 모두 준비된 뒤 한 번에 머지한다.** 배포를 1회로 줄인다
- 머지 전에 운영 데이터로 홈 화면을 확인한다. 홈은 심사 중 가장 많이 크롤링되는 페이지이고, 이번 작업은 그 히어로를 건드린다

## 10. 하지 않는 것

- `Region` 테이블을 고치지 않는다. §3.2의 불일치는 별도 사안이다
- `umd` 표기를 정규화하지 않는다. `돌산읍 우두리`를 `우두리`로 자르면 다른 리와 섞이고, 면 단위로 합치면 없는 집계를 만든다
- 기존 `NearbyPriceComparison`을 바꾸거나 없애지 않는다
- `lib/seo/indexable.ts`·`narrative` 계열을 건드리지 않는다. 이번 작업은 색인·메타 설명과 무관하다
- 홈의 다른 섹션(브리핑·청약 보드·허브)을 건드리지 않는다
- 새 데이터를 수집하지 않는다. 스냅샷은 기존 `Transaction`에서 파생한다
