# 5-3단계 · 가이드 28편 데이터 근거형 재작성

- 작성일: 2026-10-23 · 상태: 방식 A(직접 재작성) 승인, 샘플 2편 톤 승인(2026-10-23)
- 초안: `content/guides/<slug>.md` (앞머리 title·summary + 본문 마크다운) · 샘플 시안: `docs/superpowers/mockups/2026-10-23-guide-samples.html`

## 원칙
- 모든 글이 같던 틀(핵심 요약 → 개념 → 방법 → 유의점 → 더 알아보기)을 버리고, 글마다 임장ON 운영 데이터에서 나온 고유한 숫자 한두 개를 중심으로 쓴다.
- 숫자는 운영 DB 읽기전용 집계(2026-10-23)이고, 글 끝에 "집계: 임장ON, … 원자료 기준(조회일)"을 적는다. 계속 바뀌어야 하는 숫자는 기존 실시간 데이터 블록(`[[data:…]]`)으로 둔다.
- 바뀌기 쉬운 정책 수치(혼인 기간·소득 기준·LTV 비율·지원 금액)는 적지 않고 공식 확인 경로로 안내한다.
- 사이트가 실제로 보여주는 기능만 언급한다(코드로 확인). 예: 거래 데이터 특이사항, 층별 프리미엄, 청약 결과, 배정 초등학교.
- 언어모델 초안이므로 기존 자동 생성 고지는 유지한다.
- 가드레일(`runGuideGuardrails`: 분량 800~6000자, 금지 표현)과 데이터 블록 키를 모두 통과해야 한다. 원문보다 짧은 글은 데이터 절을 더해 800자 이상으로 맞췄다.

## 반영
- `scripts/guide/apply-rewrites.ts`: 게시된 글만 title·summary·body·reviewedAt을 바꾸고 publishedAt은 유지한다. 초안 하나라도 검증에 실패하면 아무것도 쓰지 않는다. 기본은 dry-run이고 `--apply`일 때만 쓴다. 쓴 뒤 `/guide`와 동적 라우트 `/guide/[slug]`(page)를 재검증한다. 한글 slug 경로를 직접 넘기지 않는다(`/api/revalidate`에 `routes` 추가). 결과에 재검증 성공 여부(`revalidated`)를 함께 보고한다.
- 순서: 머지·배포 → 박스에서 운영 Guide 28행 백업(COPY → /opt/imjang/backups) → dry-run → `--apply` → 운영 가이드 페이지 몇 곳을 직접 열어 새 본문 확인(재검증 실패 시 최대 24시간 옛 본문).
- 운영 dry-run(읽기전용, 2026-10-23): 28편 모두 대상, 건너뜀 0.

## 확인한 사실관계 정정(작성 중)
- 청약 공고 `regionCode`는 청약홈 3자리 코드(100 서울, 410 경기, 400 인천)다. 행정 코드(11·41·28)로 잘못 세면 수도권 집중이 사라진다.
- 병원 목록은 지역·종별·이름으로 거른다(진료과 필터 없음).
- 통학구역 비율(18.8%)은 학구 기준이고, 학교 기준이 아니다.
