# 허브 콘텐츠 보강 v2 설계 (전체 허브: 요약 확장 + 활용 가이드)

작성일: 2026-07-01
상태: 승인 대기 (사용자 리뷰 전)
선행: `2026-07-01-hub-summary-design.md`(v1, 6개 허브에 등록 수 기반 분포 요약 추가 — PR #178)

## 배경 / 목표

v1은 6개 허브에 "정체 + 지역 분포" 1~2문장 요약을 SSR로 추가했다. 하지만 (a) 문장 골격이 템플릿이라 카테고리 간 차별성이 약하고, (b) 4개 허브(apt·subscription·school·childcare)는 아직 미적용이다.

v2 목표: **전체 허브**에 두 가지를 얹어 콘텐츠를 실질적으로 보강한다.
1. **카테고리별 풍부한 요약** — 각 카테고리의 실데이터로 하이라이트 팩트를 요약에 추가(정체 + 분포 + 하이라이트).
2. **활용 가이드 문단** — 카테고리별 손으로 쓴 고정 에디토리얼 문단(2~3문장, 데이터 의존 없음).

근접중복 탈출은 여전히 데이터 요약(분포+하이라이트)이 담당하고, 가이드는 카테고리별 고유 텍스트로 페이지 깊이를 더한다.

## 아키텍처 — v1의 3계층 확장

기존 `lib/hub-summary/`를 재사용한다.

### 요약 확장 (블록 1)

`HubSummaryData`에 선택적 `highlights?: string[]` 추가. 각 도메인 집계 함수가 카테고리별 하이라이트 문장을 생성해 채운다. 프로즈 빌더는 `[정체] + [분포] + [...highlights]` 순으로 렌더한다.

```ts
export interface HubSummaryData {
  // ...v1 필드...
  highlights?: string[];  // 카테고리별 추가 팩트 문장 (0~2개). 없으면 정체+분포만.
}
```

- 하이라이트 문장 조립은 **순수 함수**로 분리(`lib/hub-summary/highlights/*.ts`), 카테고리별 집계 통계를 입력받아 문장을 반환 → 단위 테스트 가능.
- 하이라이트가 없는 카테고리(약국·편의점·마트·카페·전통시장)는 `highlights` 미설정 → 정체+분포+가이드로만 채운다(억지 문장 생성 금지).

### 가이드 블록 (블록 2)

- `lib/hub-summary/guides.ts` — 카테고리 키 → 가이드 문단(문자열) 정적 레지스트리(손으로 작성).
- `app/(public)/_components/hub-guide.tsx` — 서버 컴포넌트. 키를 받아 문단 렌더. 없으면 `null`.
- 데이터 의존 없음. 카테고리당 1개 문단(15개 카테고리 = 15개 고유 문단).

## 카테고리별 하이라이트 (블록 1 데이터)

집계 단위는 스코프에 맞춘다(전국→시도 무관 전체 통계; 시도/시군구 스코프→해당 스코프 내 통계). 실패 시 하이라이트 생략(요약은 정체+분포로 유지).

| 허브 | 하이라이트 문장 | 데이터 소스 |
|------|----------------|------------|
| 아파트/오피스텔/빌라 | 최근 12개월 매매·전세·월세 거래 비중, 평균 매매가 | Property: `saleCount12m`/`jeonseCount12m`/`wolseCount12m`, `saleAvgPrice12m` — **성능 주의(아래)** |
| 청약 | 접수 진행중/예정 건수, 공급유형(민영·공공 등) 분포, 총 공급 세대 | SubscriptionNotice: `status`, `category`, `totalSupply` |
| 학교 | 학교급(초·중·고·특수) 분포, 공/사립 비율 | School: `schoolKind`, `foundType` |
| 어린이집 | 운영유형(국공립·민간·가정) 분포, 평균 정원 | Childcare: `crType`, `capacity` |
| 병원 | 종별(종합병원·병원·의원 등) 분포 | Hospital: `typeName` |
| 주차장 | 공영 비율, 무료 비율 | Parking: `prkplceSe`, `chargeInfo` |
| 공원 | 유형(어린이·근린 등) 분포, 평균 면적 | Park: `parkType`, `area` |
| 충전소 | 급속/완속 비율, 총 충전기 수 | EvCharger: `chargeSpeed`, `chargerCount` |
| 약국·편의점·마트·카페·전통시장 | (추가 필드 제한) → 하이라이트 없음, 분포+가이드로 | — |

### 성능 제약 (아파트/오피스텔/빌라)

이 3개는 `force-dynamic`이고 Property는 대용량이다(수백만 행). 전국 SUM/AVG를 매 요청 실행하면 Supabase 부하 위험(메모리: 디스크 IO 병목). 따라서 property 하이라이트는:
- 가능하면 **홈 대시보드 사전계산 스냅샷 재사용**(있으면), 없으면
- `txCount12m > 0` 인덱스를 타는 **단일 경량 aggregate** 1회, 그리고 `unstable_cache`로 감싸 TTL 캐시.
- 그래도 비싸면 **하이라이트 생략**(분포만 유지). 플랜에서 실측 후 결정.

## 신규 편입 4개 허브 처리

- **apt**: 헤더에 HubSummary(정체+분포+하이라이트) + HubGuide 추가. 기존 "거래 많은 단지 TOP 30" 목록 유지.
- **subscription**: 헤더 카드에 요약+가이드 추가. 기존 필터/동적 결과 유지. 기존 description 산문은 가이드로 대체 가능.
- **school / childcare**: 기존 1줄 인트로("지역·학교급으로 좁혀보세요…")를 **가이드 문단으로 대체**하고, 데이터 요약을 추가.

## 활용 가이드 문단 규칙

- 카테고리당 2~3문장, 손으로 작성. PRODUCT.md "조용한 정보 안내자" 톤 — 사실·안내 위주, 과장·광고 문구 금지.
- 내용: 그 시설/데이터를 임장·검토 시 **무엇을 함께 보면 좋은지**. 예:
  - 학교: "학군은 배정 방식과 통학 거리에 따라 체감이 다릅니다. 설립유형(공립·사립)과 남녀공학 여부, 인근 아파트 시세를 함께 확인하세요."
  - 주차장: "주차 여건은 공영·민영, 요금, 운영시간, 24시간 개방 여부에 따라 크게 갈립니다. 목록에서 운영시간과 요금을 함께 살펴보세요."
- 전체 문단 초안은 플랜에서 카테고리별로 작성.

## 배치 / 렌더링

- 헤더 카드 안: `[정체+분포+하이라이트 요약 <p>]` → `[HubGuide 문단]`(muted, 작은 여백). 기존 리스트/필터/카드/페이지네이션 변경 없음.
- 모두 서버 컴포넌트 → 초기 HTML 포함(봇 가독). ISR 허브는 집계 캐시.
- force-dynamic 허브는 집계 호출 `.catch(() => null)` 폴백.

## 단계화 (2 페이즈, 각각 독립 배포 가능)

- **페이즈 1 — 활용 가이드 (전 15 카테고리):** guides 레지스트리 + HubGuide 컴포넌트 + 15개 허브 배선. 저위험·즉효. 신규 4개 허브에는 이 단계에서 요약 없이 가이드만 먼저 붙어도 됨(요약은 페이즈 2).
- **페이즈 2 — 카테고리별 풍부한 요약:** `highlights` 필드 + 하이라이트 집계/빌더 + 신규 4개 허브 HubSummary 배선. 도메인 그룹(property / subscription / school·childcare / medical / urban)별로 진행.

## 테스트

- **하이라이트 빌더 단위 테스트**(순수 함수): 카테고리별 통계 입력 → 기대 문장, 데이터 결측/0 케이스 폴백.
- **가이드 레지스트리 테스트**: 15개 카테고리 키 전부 문단 보유, 빈 문자열 없음.
- **집계 함수 통합 테스트**(`.env.test`): 카테고리별 하이라이트 통계 계산 검증.
- **회귀**: 기존 v1 요약·리스트 동작 유지.

## 성공 기준

1. 15개 허브 초기 HTML에 가이드 문단이 포함된다(페이즈 1).
2. 데이터 있는 카테고리는 요약에 하이라이트 문장이 추가된다(페이즈 2).
3. 데이터 없는/실패 케이스에서 페이지가 죽지 않고 폴백(요약/가이드만) 렌더.
4. 신규 4개 허브(apt·subscription·school·childcare)에 요약+가이드가 노출된다.
5. 기존 리스트/필터/카드 회귀 없음. 빌더·집계 테스트 통과.
