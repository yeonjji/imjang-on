# 신뢰 페이지 보강 설계 — privacy·terms·contact·about

작성 2026-08-07.

## 배경

AdSense 승인 심사에서 개인정보처리방침·이용약관·문의 페이지의 실질성이 신뢰 신호로 작동한다는 관찰에서 출발했다. 현황을 조사한 결과, **보강 이전에 사실 오류부터 고쳐야 하는 상태**임이 드러났다.

`/privacy` 제4조가 처리위탁 사업자로 "Vercel Inc. — 트래픽 분석 및 호스팅"을 명시하고 있으나, 2026-07-22에 OCI 자가호스팅으로 이전하여 현재 Vercel을 사용하지 않는다. 시행일은 2026-06-07로 고정돼 있고 개정 이력이 없다.

"단순 템플릿 복사가 아니라 실제 운영 정책이 반영된 형태"라는 목표의 정확한 반대 사례가 현재 방침에 있다. 이 설계의 1차 목적은 **사실 교정**, 2차 목적이 누락 조항 보강이다.

## B. `/terms` — 3개 조항 추가

기존 8개 조항은 유지하고 아래를 삽입한다.

**제3조의2 (자동 생성 콘텐츠의 고지)** *(신설)* — 가장 중요한 조항

시황 브리핑과 게시판 글은 공공기관 원문을 근거로 언어모델(OpenAI)이 문안을 작성하고, **운영자가 검수한 뒤 게시**한다는 실제 절차를 명시한다. 근거 원문의 출처를 각 글에 표기한다는 점도 함께 적는다.

재진단 문서가 지적한 AdSense 위반 항목 "manual review or curation 없는 automatically generated content"에 대해, 실제로 검수 단계가 존재한다는 사실을 공개 문서에 명시하는 의미가 있다. 어드민 검수 화면은 `app/admin/posts`에 실재한다.

**제4조의2 (데이터 정정 요청의 처리)** *(신설)* — 접수 → 원본 데이터 대조 → 정정 또는 사유 회신. 원본 자체의 오류는 원 제공기관에 문의해야 한다는 안내 포함

**제7조의2 (서비스의 변경·중단)** *(신설)* — 1인 운영 특성상 서비스 항목이 변경·중단될 수 있으며 사전 공지한다

말미에 개정 이력을 `/privacy`와 동일한 형식으로 추가한다.

## C. `/contact` — 실질 안내로 확장

현재 이메일 주소 한 줄 + 두 문장(1.1KB). 아래 구조로 재작성한다.

**1. 문의 유형별 안내** — 각 유형에 "무엇을 적어 보내야 하는지"를 구체적으로 기술

| 유형 | 함께 적어주실 내용 |
|---|---|
| 데이터 오류·정정 | 해당 화면 주소, 표시된 값, 확인하신 원본 출처 |
| 개인정보 열람·삭제 | 신청 시 사용한 이메일 주소 |
| 저작권·권리 침해 | 해당 화면 주소, 침해 사유, 권리 보유 근거 |
| 제휴·광고 | 제안 내용과 연락 수단 |

**2. 처리 절차** — 접수 → 원본 데이터 대조 → 정정 또는 사유 회신. 기한은 적지 않는다

**3. 운영 주체 정보** — 서비스명(임장ON), 운영 형태(1인 운영), 연락처(`contact@imjangon.co.kr`), 성격(공공데이터 기반 정보 제공, 부동산 중개업 아님)

## D. `/about` — 운영 실체 보강

실명을 공개하지 않으므로 "누가"가 아니라 **"어떻게 운영되는가"**로 신뢰를 만든다. 기존 4개 섹션은 유지하고 아래를 추가한다.

**데이터 갱신 주기** — 위 실측 표를 KST 기준으로 게재. 병원·약국은 부정기 수동 갱신으로 별도 표기

**운영 연혁** — 위 월 단위 연혁. "2026년 7월 자체 서버 인프라로 이전"까지 포함해 운영이 지속되고 있음을 보임

**오류를 발견하면** — 정정 요청 처리 흐름을 이용자 관점에서 서술하고 `/contact`로 연결

**운영 재원** — 광고 수익으로 서버·운영 비용을 충당하며, 부동산 중개나 특정 매물 광고는 하지 않는다는 고지. 기존 "운영 주체" 문단에 이미 일부 있으므로 독립 섹션으로 분리해 명확히 한다
