## 1. 표본 실측 (2026-10-20)

- **표본:** 운영 DB에서 최근 12개월 거래가 있는 단지를 유형별로 무작위 100곳씩 뽑았다(아파트·오피스텔·연립·다세대 = 400곳).
- **API:** 건축HUB `getBrRecapTitleInfo`(총괄표제부)·`getBrTitleInfo`(표제부)·`getBrJijiguInfo`(지역지구구역)

### 조회 키 만들기

- 우리 `Property.regionCode`와 `Transaction.regionCode`는 **시군구 단위**다(뒤 5자리 00000). 그래서 법정동 코드가 없다.
- 실거래의 동 이름(`Transaction.umd`, 예: '정자동', '덕산읍 두촌리')을 법정동 코드로 바꿔야 한다.
- 우리 `Region` 테이블은 이 변환에 쓸 수 없다. 일반구(수원·성남·부천 등)의 동이 빠져 있다(시드 결함, 메모리 기록).
- 그래서 **국토교통부 법정동코드 파일**(data.go.kr 15123287, 2026-09-29판, 5.3만 행, '존재'만 사용)을 조회표로 쓴다. 키는 (시군구코드 5자리, 시군구명 뒤의 이름)이다.
- 지번은 `Transaction.jibun`('번-지', '산' 접두는 대지구분 1)을 쓴다. 형식이 맞지 않는 지번은 0.35%다.

### 매칭 결과 (채택 = §3 조건 전부 만족)

| 유형 | 채택 | 실패 사유 |
|---|---|---|
| 아파트 | **93%** | 지번 여러 개 2 · 동 코드 없음 3(부천) · 건물 특정 불가 2 |
| 오피스텔 | **91%** | 준공연도 없음 5 · 기타 4 |
| 연립 | **97%** | 3 |
| 다세대 | **87%** | 지번 여러 개 8 · 동 코드 없음 4 · 기타 1 |

- 법정동코드 파일 없이 `Region`만 쓰면 채택률은 61~84%다.
- 남은 동 코드 실패는 부천 원미·소사·오정구(41192·41194·41196)다. 2024년 일반구 부활로 실거래 코드와 법정동 파일 코드가 엇갈리는 것으로 보인다.
- **준공연도 불일치로 탈락한 건은 0건이다.** 엉뚱한 건물에 붙은 사례는 표본에서 나오지 않았다.
- 오피스텔 중 건물이 하나인 매칭 85건의 주용도는 모두 업무시설·오피스텔·공동주택이었다. '공장'(지식산업센터 등)은 한 필지에 건물이 여럿인 경우에만 나왔고, 그런 경우는 채택하지 않았다.

## 2. 데이터 모델

```prisma
/// 국토교통부 법정동코드(존재분). (시군구코드, 동 이름) → 법정동 코드 조회표. 연 1회 교체.
model LegalDong {
  code        String @id @db.Char(10)
  sigunguCode String @db.Char(5)
  /// 시군구명 뒤의 이름: '정자동', '덕산읍 두촌리'
  name        String @db.VarChar(60)

  @@index([sigunguCode, name])
}

/// 단지(Property) 1곳당 건축물대장 매칭 결과 1행. status가 'matched'일 때만 화면에 쓴다.
model BuildingRegister {
  propertyId BigInt   @id
  /// 'matched' | 'multi_pair' | 'bad_key' | 'not_found' | 'ambiguous' | 'year_mismatch' | 'year_unknown' | 'purpose_mismatch' | 'api_error'
  status     String   @db.VarChar(20)
  bjdCode    String?  @db.Char(10)
  platGbCd   String?  @db.Char(1)
  bun        String?  @db.Char(4)
  ji         String?  @db.Char(4)

  useAprDate      DateTime? @db.Date
  structure       String?   @db.VarChar(60)
  mainPurpose     String?   @db.VarChar(60)
  etcPurpose      String?   @db.VarChar(300)
  groundFloors    Int?      // 동이 여럿이면 최고
  undergroundFloors Int?
  mainBuildingCount Int?
  households      Int?
  units           Int?      // 호수(오피스텔)
  elevators       Int?      // 승용+비상, 0이면 null
  parkingTotal    Int?      // 총괄 totPkngCnt, 없으면 표제부 자주식 합(옥내+옥외)
  bcRat           Decimal?  @db.Decimal(6, 2)
  vlRat           Decimal?  @db.Decimal(7, 2)
  seismicApplied  Int?      // 내진설계 '적용'(1)인 주건축물 수
  zoningKind      String?   @db.VarChar(20)  // 지역지구 대표의 구분명('용도지역' 등)
  zoningName      String?   @db.VarChar(60)
  hasNeighborhoodFacility Boolean @default(false)
  registerCreatedAt DateTime? @db.Date       // crtnDay(대장 생성일)
  raw        Json?
  fetchedAt  DateTime

  @@index([status])
}
```

## 3. 매칭 채택 조건 (검토 ④ 구체화)

모두 만족해야 `matched`이다.

1. 단지 실거래의 (법정동 코드, 대지구분, 번, 지)가 **하나로 모인다**. 여러 개면 `multi_pair`, 동 이름이나 지번을 변환하지 못하면 `bad_key`다.
2. 조회 결과에서 대상 건물을 하나로 특정한다.
   - 아파트: 총괄표제부가 1건이면 그것과 그 필지의 주건축물 전체를 쓴다.
   - 오피스텔·빌라: 주건축물(`mainAtchGbCd`=0) 표제부가 1건이거나, 총괄표제부가 1건이거나, 건물명이 단지명과 포함 관계로 맞는 건물이 한 이름으로 모일 때.
   - 위에 해당하지 않으면 `ambiguous`, 결과가 없으면 `not_found`다.
3. 사용승인연도(동별 `useAprDay`)가 우리 준공연도와 ±1년 안이다. 동이 여럿이면 어느 하나라도 맞으면 된다. 우리 준공연도가 없으면 `year_unknown`으로 채택하지 않는다.
4. **용도 확인:** 주용도·기타용도에 다음 말이 있어야 한다. 아니면 `purpose_mismatch`다.
   - 아파트·빌라: '공동주택' 또는 '주택'
   - 오피스텔: '오피스텔'·'업무'·'공동주택' 중 하나

## 4. 수집

- `scripts/ingest/building-register/`, 온박스 타이머로 매일 실행한다. 100분 시간 예산과 한도 초과 시 즉시 중단은 1단계와 같다.
- **대상:** 모든 Property(redirect 아님) 약 27.6만 곳 중 `BuildingRegister` 행이 없는 단지를 우선한다.
  - 아파트 → 오피스텔 → 연립 → 다세대 순, 같은 유형 안에서는 최근 12개월 거래가 많은 순(사용자 노출이 많은 페이지부터).
  - `api_error` 행은 다음 실행에서 다시 받는다.
  - 건축물대장은 거의 바뀌지 않으므로, 다 채운 뒤에는 새 단지만 받는다. 전체 재수집은 범위 밖이다.
- **호출:** 단지당 최대 3번(총괄표제부·표제부·지역지구). 키를 못 만든 단지는 호출하지 않는다.
  - 전체 약 83만 건. 개발계정(하루 1만)으로는 약 83일, 증설(하루 10만 가정) 후 약 9일.
- **법정동코드 파일:** 별도 적재 스크립트(`pnpm ingest:legal-dong`, 연 1회 수동)로 받는다. 받는 방식은 학구도와 같은 data.go.kr 파일데이터 경로다.
- 같은 (지번 키)를 공유하는 단지가 있어도 각각 따로 판정한다. 호출 중복은 허용한다.

## 6. 테스트

- **유닛:**
  - 키 만들기(동 이름 변환, 산 지번, 지번 여러 개 → multi_pair)
  - 건물 특정 규칙(유형별)
  - 연도 ±1
  - 용도 확인
  - 필드 정규화(0 → null 규칙, 승강기 합, 주차 폴백, 내진 적용 수)
  - 근생 판정
- **통합:** 수집 러너(한도 중단·이어받기·api_error 재시도·시간 예산), 조회
- **렌더링:**
  - 유형별 블록
  - 내진 '미적용' 문구가 없음
  - 근생 줄은 빌라에서만
  - 빈 값 행 숨김
- **e2e:** 시드 1단지(아파트) + 1단지(빌라 근생)
- **실데이터 QA:** 유형별 매칭된 페이지 각 1곳 + 부천 단지(숨김 확인)
