# 상세 페이지 공공데이터 보강 로드맵

- 작성일: 2026-10-15
- 상태: 초안(사용자 검토 대기)
- 성격: 단계 목록. 각 단계는 시작할 때 별도 설계 문서(spec) → 구현 계획 → PR을 거친다. 한 번에 한 단계만 진행한다.

## 1. 목적

AdSense 승인(최우선)을 위해, 남아 있는 공개 상세 페이지에 **아직 수집하지 않은 공공데이터**를 새로 들여와 비교·해석 정보와 임장에 쓸 정보를 넣는다.

- 새 카테고리·새 페이지는 만들지 않는다. 기존 상세 페이지 안에만 넣는다.
- 페이지를 줄이거나 없애는 방향(D1 등)은 이번 로드맵에서 다루지 않는다.

### 선정 원칙

1. **엔티티 단위 데이터만.** 단지·공고·학교마다 값이 다른 데이터를 고른다. 시군구 단위 데이터(미분양, 대기질, 인구)는 같은 구 페이지 수천 개에 같은 문단을 만들어 replicated content를 키우므로 제외한다.
2. **임장 활용도.** 실제로 집을 보러 다닐 때 묻는 정보(관리비, 배정 학교, 주차, 경쟁률)를 우선한다.
3. **출처 표기.** 새 소스는 `lib/data-sources.ts` 레지스트리에 추가하고 `SourceCaption`으로 표기한다.

## 4. 단계 진행 규칙

- 단계마다 `docs/superpowers/specs/YYYY-MM-DD-<주제>-design.md`를 따로 쓰고 승인받은 뒤 구현한다.
- spec 작성 전 표본 호출로 채움률을 실측해 spec에 적는다.
- **개발 착수 전 UI 시안을 사용자에게 먼저 확인받는다(필수).** 화면에 어디에, 어떤 형태로 보여줄지 시안(artifact 등)으로 합의한 뒤에만 구현을 시작한다. 시안 확정본을 spec에 링크한다.
- PR 하나에 마이그레이션·수집·화면을 함께 담는다.
- 단계가 끝나면 이 문서의 상태 열을 갱신한다.
