# 가이드(/guide) 콘텐츠 채우기 + 목록 섹션화 설계

작성일: 2026-06-30

## 배경

어제 `/guide` 시스템(생성 파이프라인 + 공개 라우트 + 시드 7개)을 만들었다. 이제
실제 가이드 글을 채워 넣으려 한다. 동시에 두 가지 개선이 필요하다.

1. 생성 글의 구조를 독자 친화적으로 업그레이드한다(현재는 `핵심요약 → 소제목 → 참고자료`
   골격만 있음).
2. `/guide` 목록이 "글만 쭉 나열"되는 평평한 2열 그리드라 분야 구분이 약하다. 분야별
   섹션으로 구획한다(브리핑은 오늘 신문형 테이블로 바뀌었지만, 상록 가이드는 카드 섹션이
   맞다).
3. 네비게이션에서 `가이드`가 데이터 메뉴(청약·금융) 사이에 껴서 어색하다.

브리핑(`/board`)은 날짜성 뉴스라 건드리지 않는다. 이 설계는 상록 가이드(`/guide`)만 대상.

## 렌더링 계약(반드시 준수)

`app/(public)/guide/[slug]/page.tsx`는 `splitSummary(guide.body)`로 본문을 가공한다.

- `## 핵심 요약` 블록을 떼어내 하단 콜아웃(`ArticleSummary`)으로 렌더한다.
  → **새 구조도 반드시 `## 핵심 요약`으로 시작**해야 콜아웃이 동작한다.
- DB `summary` 필드 = "한 줄 요약"(H1 밑 + 메타 description). DB `title` = 제목.
- 출처는 `PostSource` 컴포넌트가 `sourceName/sourceUrl/sourceDate`로 따로 렌더한다.

## 작업 1 — 네비게이션 순서 변경

`app/(public)/_components/nav.tsx`의 데스크톱 링크 순서를 데이터 먼저, 편집물 끝으로 정리.

- 변경 전: 실거래가 · 청약 · **가이드** · 금융 · 생활 · 브리핑
- 변경 후: 실거래가 · 청약 · 금융 · 생활 · **가이드 · 브리핑**

`FinanceDropdown`/`LifeDropdown`은 그대로, `<Link href="/guide">가이드</Link>`를
`LifeDropdown` 뒤(브리핑 앞)로 이동만 한다. 모바일 드로어(`mobile-drawer.tsx`)도 동일
순서로 맞춘다.

## 작업 2 — 생성 프롬프트 업그레이드

`lib/guide/generate.ts`의 `SYSTEM_PROMPT`을 9단 독자 친화 구조로 교체한다. 단, 고정
라벨을 모든 글에 강제하면 양산형 콘텐츠로 보일 위험이 있으므로 **고정 앵커 3개만 강제**하고
중간 소제목은 내용 주도로 둔다.

### 9단 의도 → 실제 구조 매핑

| 작성자 9단 | 반영 위치 |
|---|---|
| ① 제목 | DB `title` (25자 내외) |
| ② 한 줄 요약 | DB `summary` (한 문장) |
| ③ 확인할 수 있는 내용 | `## 핵심 요약` 3~4 불릿(핵심어 **굵게**) → 콜아웃 |
| ④ 이 정보가 필요한 사람 | 도입 문단에 자연스럽게 녹임(별도 섹션 X) |
| ⑤ 핵심 개념 / ⑥ 확인·이용 방법 / ⑦ 주의할 점 | `## 소제목` 2~3개(내용 주도 자유 작명) |
| ⑧ FAQ 3~5 | `## 자주 묻는 질문`(Q/A) |
| ⑨ 마무리 + CTA | `## 더 알아보기`("확인 필요" 문구 + 내부 링크) |
| (출처) | `## 참고 자료` → `PostSource` |

### 본문 골격(프롬프트가 생성할 마크다운)

```
## 핵심 요약
- **핵심어**: ...
- ...
(도입 문단에 "이 정보가 필요한 사람"을 자연스럽게 서술)

## (핵심 개념 소제목 — 내용 주도)
## (확인·이용 방법 소제목 — 내용 주도)
## (주의할 점 소제목 — 내용 주도)

## 자주 묻는 질문
**Q. ...?** A. ...
(3~5개)

## 더 알아보기
조건은 달라질 수 있으니 공식 공고를 함께 확인하는 것이 좋습니다.
관련 정보 확인하기 → [{relatedLabel}]({relatedHref})

## 참고 자료
출처: ...
```

### 프롬프트 변경 핵심 지시

- 고정 앵커 강제: `## 핵심 요약`(맨 위), `## 자주 묻는 질문`, `## 더 알아보기`,
  `## 참고 자료`. 중간 본문 소제목은 내용에 맞게 자유 작명(2~3개).
- "이 정보가 필요한 사람"은 별도 섹션이 아니라 도입 문단에 녹인다.
- 마무리에 "조건은 달라질 수 있다 / 공식 공고 확인" 류 확인필요 문구를 반드시 포함.
- 마무리 CTA는 입력으로 받은 `relatedLabel`/`relatedHref`를 그대로 링크한다.
- 기존 금지 규칙(시세 단정 전망·투자권유·과장·근거 외 수치 날조) 유지.
- 분량: 공백 제외 한글 1,000~6,000자.

### 가드레일(`lib/guide/guardrails.ts`)

- 기존 금지표현/출처/분량 체크 유지. **하드 체크 추가는 하지 않는다**(확인필요 문구·CTA
  존재 여부를 정규식으로 강제하면 오탐 위험). 프롬프트 지시로 충족하고, 어드민 검수에서
  최종 확인.

## 작업 3 — 시드 확장(7 → 14)

`lib/guide/seeds.ts`의 `GuideSeed`에 CTA 내부 링크 필드를 추가하고, 카테고리당 2편이
되도록 신규 7개를 추가한다.

### 타입 변경

```ts
export interface GuideSeed {
  key: string;
  category: GuideCategory;
  title: string;
  angle: string;
  source: { name: string; url: string; date: string; excerpt: string };
  related: { label: string; href: string }; // 신규: 마무리 CTA 내부 링크
}
```

기존 7개 시드에도 `related`를 채운다. 내부 링크는 실제 존재하는 라우트만 사용한다
(예: `/list`, `/subscription`, `/jeonse-guarantee`, `/finance`, `/medical/hospital`,
`/medical/pharmacy`, 생활 관련 라우트 등). 라우트 존재는 구현 시 확인한다.

### 신규 7개 주제(카테고리당 2편 균형)

각 카테고리에 1편씩 추가. 주제는 기존편과 겹치지 않는 상록 주제로 한다(예시, 구현 시 확정):

- REALESTATE: "전용면적·공급면적, 평수 계산 이해하기"
- SUBSCRIPTION: "청약통장 종류와 1순위 조건 이해하기"
- FINANCE: "디딤돌·보금자리 등 정책대출 한눈에 보기"
- MEDICAL: "동네 병원·전문과목 찾는 법"
- CHILDCARE: "어린이집 입소 대기와 신청 절차"
- SCHOOL: "학교알리미로 학교 정보 확인하는 법"
- LIFE: "생활 인프라(마트·공원·주차) 따져보는 법"

`validateGuideSeeds()`는 그대로 동작(카테고리 커버리지·key 중복 검사). 신규 key는 고유하게.

## 작업 4 — 목록 섹션화(`app/(public)/guide/page.tsx`)

현재 평평한 2열 그리드를 분야별 섹션으로 바꾼다.

- **필터 없음(전체)**: 카테고리별 섹션으로 묶어 위→아래로 쌓는다. 각 섹션 =
  카테고리 라벨 소제목 + 해당 카테고리 카드(2~3개) 가로 그리드. 카드가 없는 카테고리는
  섹션 생략. 페이지네이션은 전체 보기에서 숨긴다(섹션 뷰는 분야별 소수 노출이므로).
- **카테고리 칩 선택 시**: 기존 동작 유지(해당 카테고리 카드 그리드 + 페이지네이션).
- 상단 히어로 카드·칩 필터는 그대로.

데이터 조회: 전체 보기에서는 카테고리별로 묶을 수 있도록 충분한 행을 가져오거나
(`listPublishedGuides`에 카테고리 묶음 옵션 추가 또는 카테고리별 조회), 14편 규모에서는
전체를 한 번에 가져와 클라이언트 그룹핑해도 무방하다. 구현 시 `lib/guide/queries.ts`를
확인해 가장 단순한 방법을 택한다.

## 작업 5 — 14편 생성·검수·게시

1. 업그레이드된 프롬프트 + 확장 시드로 14편 DRAFT 생성
   (`scripts/generate-guides.ts` / `generate-guides.yml`). 기존 7편이 이미 게시돼 있으면
   `restructure.ts --in-place`로 본문만 새 구조로 교체(게시일 리셋 방지)하거나, dedupeKey
   기준 재생성 정책을 확인해 처리한다.
2. 어드민(`/admin/guides`)에서 가드레일 PASS·내용 검수 후 게시.

생성/재구조화 메커니즘(기존 key 스킵 여부, 게시본 처리)은 구현 계획 단계에서
`scripts/generate-guides.ts`를 읽어 확정한다.

## 범위 밖(후속)

- 본문 `## 자주 묻는 질문`에서 FAQPage JSON-LD 자동 추출(현재는 마크다운으로만 렌더).
- 카테고리 FAQ(랜딩) vs 본문 FAQ 내용 정합성 정리.
- 시드를 카테고리당 3편 이상으로 추가 확장.

## 검증 기준

- 나브: 데스크톱·모바일 모두 `… 생활 · 가이드 · 브리핑` 순서.
- 생성 글: `## 핵심 요약`으로 시작 → 상세 페이지에서 콜아웃 분리 정상. FAQ·마무리 CTA
  내부 링크 동작. 가드레일 PASS.
- 목록 전체 보기: 카테고리별 섹션 노출, 빈 카테고리 생략, 카테고리 칩 필터 정상.
- `pnpm exec tsc --noEmit` 통과, 가이드 관련 기존 테스트 통과.
