# 홈 히어로 레이아웃 재구성 설계

## 1. 무엇을 바꾸는가

홈 히어로와 「동네별 최근 실거래가」 카드를 **형제로 분리**하고, 통계 바를 두 영역 아래 전체폭 밴드로 옮긴다. 기능 변경은 없다 — 배치만 바꾼다.

```
변경 전                          변경 후
┌──────────────────────┐        ┌───────────────┐ ┌────────┐
│ 파란 히어로 박스        │        │ 파란 히어로 박스 │ │ 흰 카드  │
│ ┌──────┐ ┌────────┐ │        │ 검색·인기지역    │ │ 필터 3줄 │
│ │검색   │ │흰 카드  │ │        │ 버튼·카테고리    │ │ 거래 4건 │
│ │아이콘 │ │거래 8건 │ │        └───────────────┘ │ 더보기   │
│ │통계   │ │        │ │                          └────────┘
│ └──────┘ │        │ │        ┌────────────────────────────┐
│  ↑158px  └────────┘ │        │ 통계 4칸 (전체폭)            │
│  죽은 여백            │        └────────────────────────────┘
└──────────────────────┘
```

## 2. 현재 문제의 원인

측정값은 전부 **운영 페이지 1440px 뷰포트 실측**이다(2026-09-22).

카드가 히어로의 `p-10`(좌우·상하 40px) **안에** 있다. 그래서 히어로 박스 전체가 카드 높이에 끌려 922px로 부푸는데, 왼쪽 열 콘텐츠는 764px뿐이다. 차액 **158px이 왼쪽 아래 죽은 여백**으로 남는다.

원인이 "카드가 길어서"가 아니라 "카드가 히어로 패딩 안에 있어서"라는 점이 중요하다. 분리하면 각 열이 자기 콘텐츠 높이를 갖는다.

| | 변경 전 | 변경 후 |
|---|---|---|
| 히어로 박스 | 922px (카드 높이에 끌림) | 607px (자기 콘텐츠) |
| 왼쪽 열 콘텐츠 | 764px | — |
| 카드 | 840px (8행) | 606px (4행+더보기) |
| 죽은 여백 | **158px** | **없음** (높이차 1px) |

## 3. 새 구조

`app/(public)/page.tsx`가 래퍼를 갖고, 히어로와 카드를 형제로 둔다. 새 컴포넌트는 만들지 않는다.

```
<section className="mx-auto max-w-[1180px] px-6 py-12">
  {/* panel이 null이면 그리드를 켜지 않는다 — 아래 폴백 문단 참고 */}
  <div className={panel ? 'xl:grid xl:grid-cols-[69fr_31fr] xl:gap-10 xl:items-start' : ''}>
    <HeroSection popularRegions={popularRegions} />
    {panel}
  </div>
  <div className="@container mt-6">
    <StatsBar stats={stats} />
  </div>
  …
```

`panel`은 지금 `page.tsx`가 `panelSlot`에 넘기던 것과 같은 식이다 — 인기 지역 1위 시군구와 최상위 동이 모두 있을 때만 `<DongTransactionPanel>`이고, 아니면 `null`이다.

**`HeroSection`에서 `panelSlot`·`statsSlot` prop을 둘 다 제거한다.** 검색·인기지역·버튼·카테고리만 남은 형태로 되돌아가고, 슬롯 패턴이 사라져 시그니처가 `{ popularRegions }` 하나로 줄어든다.

**폴백은 래퍼로 옮긴다.** 지금 `hero-section.tsx`가 "`panelSlot`이 없으면 그리드 클래스를 켜지 않는다"를 담당하는데, 그 판단이 래퍼로 이동한다. 이유는 그대로다 — 명시적 `31fr` 트랙은 콘텐츠가 없어도 자기 몫의 공간을 차지해 오른쪽에 400px 빈 칸을 남긴다. 통계 밴드는 패널 유무와 무관하게 항상 전체폭이다.

### 3.1 비율과 실폭

컨테이너 `max-w-[1180px] px-6` → 내부 1132px. `gap-10`(40px)을 빼면 1092px을 69:31로 나눈다.

```
히어로  753px   (p-10 빼면 콘텐츠 673px)
카드    339px   (p-5 빼면 콘텐츠 297px)
```

카드 콘텐츠 297px은 **분리 전(339px)보다 42px 좁다.** 히어로 패딩 밖으로 나오며 얻은 폭보다 비율 변경으로 잃은 폭이 크기 때문이다. §4.2에서 이 폭에 필터가 들어가는지 확인한다.

## 4. 카드

### 4.1 노출 개수와 더보기

**4건 노출.** 5건 이상이면 목록 하단에 「거래 내역 더보기」를 둔다.

4건인 이유는 높이 균형이다. 통계가 빠진 히어로는 607px인데, 행 하나가 약 71px이다.

| 행 수 | 카드(더보기 포함) | 히어로(607) 대비 |
|---|---|---|
| **4행** | **606px** | **−1px** |
| 5행 | 671px | +64px |
| 6행 | 743px | +136px |
| 8행 | 885px | +278px |

**더보기는 클라이언트 토글이다.** 서버가 12건을 내려주고 4건만 그리다가, 누르면 나머지를 펼친다. 추가 요청이 없어 로딩·실패 상태가 새로 생기지 않는다 — 이 패널은 이미 9가지 뷰 상태(`resolvePanelView`)를 갖고 있어 상태를 더 늘리지 않는 편이 안전하다.

조회 상한을 **8 → 12**로 올린다. 4건 노출에서 더보기로 얻는 게 8건이 된다. 바뀌는 것은 상수 하나뿐이고 조회 방식·응답 형식·인덱스 사용은 그대로다.

- `app/api/dong-transactions/route.ts`의 `limit: 8`
- `app/(public)/page.tsx` 프리렌더의 `limit: 8`

**필터를 바꾸면 펼침 상태를 접는다.** 펼친 채로 지역이 바뀌면 새 결과 12건이 한꺼번에 쏟아져, 앞 결과의 연장처럼 읽힌다. `sigunguCode`·`umd`·`propertyType`·`deal`이 바뀔 때 리셋한다.

### 4.2 필터 3줄

현재는 `flex-wrap`이라 폭에 따라 줄이 갈린다. 명시적으로 3줄로 고정한다.

```
[시도 ▾] [시군구 ▾]
[동 ▾] [유형 ▾]
[전체][매매][전세][월세]
```

각 줄의 실폭(1440px 기준, 셀렉트 폭은 최장 옵션이 정한다):

| 줄 | 구성 | 실폭 | 콘텐츠 297px |
|---|---|---|---|
| 1 | 시도 155 + 시군구 95 + gap 8 | 258px | 들어감 |
| 2 | 동 83 + 유형 95 + gap 8 | 186px | 들어감 |
| 3 | 거래유형 탭 | 175px | 들어감 |

시도 셀렉트가 155px인 것은 최장 옵션이 `전남광주통합특별시`(9자)이기 때문이다. 이 값이 1줄의 폭을 지배하므로, 시도 목록이 바뀌면 재측정이 필요하다.

### 4.3 하단

출처 표기(`SourceCaption`, 국토교통부)와 「자세히 보기」를 그대로 둔다.

## 5. 반응형

**`xl`(1280px) 유지.** 아래는 1024px 실측이다.

```
카드 바깥 290px / 콘텐츠 248px
필터 1줄  258px  → 248px를 넘겨 줄바꿈
거래 행           → 카드 경계 밖으로 넘침(건물명·금액 2건 확인)
```

Tailwind 기본 브레이크포인트에서 `lg`(1024)는 위처럼 깨지고 `xl`(1280)은 깨끗하다(넘침 0건, 가로 스크롤 없음). 그 사이에 임의 브레이크포인트를 만들 이유는 약하다 — 흔한 노트북 폭(1366·1440·1512)이 전부 1280 이상이다.

`xl` 미만은 세로로 쌓는다.

```
1. 히어로
2. 카드 (폭 100%)
3. 통계 밴드
```

## 6. 컨테이너 쿼리 — 이 작업의 유일한 함정

`StatsBar`는 뷰포트가 아니라 **컨테이너 폭**으로 4열/2열을 정한다(`@4xl:grid-cols-4`, 임계 896px). 지금은 히어로 왼쪽 열의 `@container`가 그 기준을 제공한다.

통계를 밖으로 빼면 그 조상을 잃는다. **`container-type` 조상이 없으면 `@4xl:`은 조용히 무시된다** — 빌드도 통과하고 ESLint도 통과하고 에러도 없이, 폭이 1132px인데 2열로 렌더된다. 시뮬레이션에서 실제로 재현했다.

따라서 **새 밴드 래퍼에 `@container`를 붙인다.** 붙인 뒤 4열로 바뀌는 것까지 확인했다.

임계값(`@4xl` = 896px)은 바꾸지 않는다. 밴드 폭이 기존 임계에 그대로 맞는다.

| 뷰포트 | 밴드 폭 | 열 |
|---|---|---|
| 1440 | 1132px | 4열 |
| 1280 | 1132px | 4열 |
| 1024 | 976px | 4열 |
| 768 | 720px | 2×2 |
| 390 | 342px | 2×2 |

## 7. 검증

**레이아웃 실측** — 1440 / 1280 / 1024 / 768 / 390px에서:
- 가로 스크롤 없음
- 카드 안에서 셀렉트·거래 행이 경계를 넘지 않음
- 필터가 의도한 3줄로 떨어짐
- 히어로와 카드의 높이가 서로에게 끌려가지 않음

**컨테이너 쿼리 회귀 테스트** — `StatsBar`를 `@container` 조상 없이 렌더하면 4열 클래스가 무력화된다. 이건 눈으로만 잡히고 빌드로는 안 잡히므로 계약으로 고정한다: 밴드 래퍼에 `@container`가 있다는 것을 SSR 마크업에서 단언한다.

**폴백 경로** — `popularRegions`가 비었거나 `dong_options` 스냅샷이 없을 때 패널이 없어도 히어로가 전체폭으로 온전히 렌더되고, 통계 밴드는 그대로 나온다.

**기존 테스트 갱신** — `tests/components/hero-section.test.tsx`가 `statsSlot`·`panelSlot`을 넘기고 있다. prop이 사라지므로 새 시그니처에 맞춰 고치고, 슬롯 순서를 검증하던 단언은 래퍼 구조에 대한 단언으로 옮긴다.

## 8. 하지 않는 것

- 검색·인기지역·카테고리 이동, 실거래가 조회 API의 조회 방식과 응답 형식, 지역·거래유형 필터 동작, 상세 페이지 이동, 통계 수치와 조회 로직
- SEO 메타데이터, URL 구조, 사이트맵, ISR·캐싱 정책
- 색상·타이포그래피·그림자 등 디자인 토큰. 히어로는 `rounded-[28px]`, 카드는 `--radius-card`(22px)로 현행 유지
- 상세 페이지(`/apt`·`/villa`·`/officetel`)의 동네 거래 섹션 — 이번 범위 밖이다
- `@4xl` 임계값 조정, 아이콘 크기 변경

애드센스 심사 중이므로 페이지 구조·콘텐츠를 이 범위 밖으로 넓히지 않는다.
