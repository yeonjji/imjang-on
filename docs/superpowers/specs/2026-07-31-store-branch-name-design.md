# 상가 지점명 표기 (`씨유 포이사거리점`)

작성일: 2026-07-31

## 문제

`/amenity` 목록에서 체인점은 상호명이 전부 같게 보인다. 편의점 목록에 `씨유`가 여러 줄 나오면 어느 것이 어디 지점인지 구분되지 않는다. 지점명이 이름에 드러나야 한다.

## 조사 결과 (실측)

공공데이터 `storeListInUpjong` API를 직접 호출해 편의점 5,000건을 분석했다.

### 지점명은 이미 데이터에 있다 — 두 필드에 쪼개져서

원본 응답에는 `bizesNm`(상호명)과 `brchNm`(지점명)이 있고, `scripts/ingest/amenities/adapter-store.ts:56`은 `bizesNm`만 읽고 `brchNm`을 버린다.

중요한 것은 **`brchNm`이 독립된 지점명이 아니라 `bizesNm`에서 잘려나간 꼬리**라는 점이다. 둘을 공백 없이 이어붙여야 원래 상호가 복원된다.

```
bizesNm='씨유켄싱턴리조트'   brchNm='남원점'   → 씨유켄싱턴리조트남원점
bizesNm='지에스25익산'      brchNm='오거리점'  → 지에스25익산오거리점
bizesNm='미니스톱'          brchNm='서울역점'  → 미니스톱서울역점
bizesNm='세븐일레븐포이중앙'  brchNm=''        → 세븐일레븐포이중앙
```

`brchNm` 채움률은 편의점 41.8%다. 나머지 58.2%는 `bizesNm` 하나에 지점명이 다 들어 있다.

### 운영사 노이즈

`brchNm`이 `'코리아'`인 건이 표본의 7.9%(394건)다. 지점명이 아니라 **코리아세븐㈜**(세븐일레븐 운영사)의 상호가 흘러든 값이다. 이 경우 `bizesNm`이 `'…점주'`로 끝나는 형태가 많다(`'세븐혜화점주'` = 세븐일레븐 혜화점 + 주코리아세븐).

버리고 꼬리 `'점주'`를 `'점'`으로 되돌리면 정확히 복원된다.

```
'세븐혜화점주'   + '코리아' → (버림) → '세븐혜화점' → '세븐 혜화점'
'세븐효창공원점' + '코리아' → (버림) → '세븐효창공원점' → '세븐 효창공원점'
```

### 재수집의 가치

`brchNm`을 붙였을 때와 아닐 때, 같은 시군구 안에서 표시 이름이 겹치는 비율:

| | 시군구 내 중복 잔존 |
|---|---|
| 현재 저장된 `name`만 | 6.16% |
| `brchNm` 합침 | **0.32%** |

29.3%의 행이 이름을 되찾는다(`미니스톱` → `미니스톱 서울역점`). 재수집할 값어치가 있다.

### 브랜드 접두 분리

`씨유포이사거리점`을 `씨유 포이사거리점`으로 만들려면 브랜드 접두를 알아야 한다. 편의점은 소수 브랜드가 지배한다.

| 브랜드 | 비율 | | 브랜드 | 비율 |
|---|---|---|---|---|
| 씨유 | 26.2% | | 이마트24 | 7.5% |
| 세븐일레븐 | 15.2% | | 미니스톱 | 2.1% |
| GS25 | 14.4% | | CU | 1.7% |
| 지에스25 | 11.6% | | 스토리웨이 | 0.1% |
| 세븐 | 11.1% | | emart24 | 0.0% |

합계 **89.9%**. 미인식 10.1%는 대부분 개인 점포(`'에이원'`, `'금성세일마트'`)라 원래 이름이 고유하므로 분리가 불필요하다.

위 표는 `지에스`(25 없음) 표기를 뺀 측정이다. 미인식 건에 `'지에스노원하계점'`·`'지에스압구정유림점'`처럼 이 표기가 있어, 아래 설계의 브랜드 목록에는 `지에스`를 포함한다. 최장 일치를 쓰므로 `지에스25`가 우선 매칭되어 충돌하지 않는다.

**설계에 확정된 브랜드 목록(`지에스` 포함)으로 정리 규칙 전체를 적용한 결과:**

| | |
|---|---|
| 정상 `브랜드 + 지점명` | **90.0%** |
| 이상값 | **0%** |
| 원본 이름 유지(개인 점포 등) | 10.0% |

### 카페는 브랜드 분리를 하지 않는다

카페도 같은 결합 패턴이지만(`'컴포즈커피서산'` + `'석림점'`) 브랜드가 파편화돼 있다(이디야커피·투썸플레이스·메가엠지씨커피·컴포즈커피·엔제리너스커피·커피베이·더벤티…). 개인 카페 비중도 크다. 목록 유지비가 커지고 커버리지는 낮아, 카페·마트는 결합까지만 하고 브랜드 분리는 하지 않는다.

## 범위

- **대상:** `Store` 테이블을 쓰는 `/amenity` 카테고리 — `convenience`, `cafe`, `mart`.
- **브랜드 접두 분리:** `convenience`만.
- **범위 밖:** 전통시장(`market`, 별도 테이블), 병원·학교·약국 라우트, meta title, 정렬·필터 로직.

## 설계

### 데이터

`Store`에 컬럼을 하나 추가한다.

```prisma
branchName String? @db.VarChar(60)   // brchNm 원본. 가공은 표시 시점에.
```

`adapter-store.ts`는 `brchNm`을 **가공 없이 그대로** 저장한다. 정리 규칙을 수집이 아니라 표시 시점에 두는 이유: 규칙이나 브랜드 목록을 고칠 때 약 31만 건을 다시 받지 않아도 되고, 순수 함수로 테스트할 수 있다.

기존 행은 `sourceId` upsert이므로 재수집만 하면 채워진다. 별도 백필 스크립트가 필요 없다.

### 표시 규칙

`lib/amenity/store-name.ts` — 순수 함수. DB·네트워크 접근 없음.

```ts
export function displayStoreName(
  store: { name: string; branchName?: string | null },
  opts?: { splitBrand?: boolean },
): string;
```

단계는 이 순서로 적용한다.

1. `branchName`이 운영사 노이즈면 버린다. 현재 목록은 `{'코리아'}` 하나.
2. `name + branchName`을 **공백 없이** 결합한다.
3. 꼬리 `'점주'`를 `'점'`으로 바꾼다.
4. `opts.splitBrand`가 참이면 알려진 브랜드 접두를 최장 일치로 떼고 공백을 넣는다. **기본값은 거짓**이라 호출부가 명시적으로 켜야 한다.
5. 브랜드를 못 찾거나 지점부가 비면 **원본 `name`을 그대로 반환한다.**

브랜드 목록은 이 파일에 상수로 둔다: `세븐일레븐`, `씨유`, `지에스25`, `지에스`, `이마트24`, `미니스톱`, `스토리웨이`, `emart24`, `GS25`, `CU`, `세븐`. 최장 일치가 필수다 — `세븐일레븐`이 `세븐`보다, `지에스25`가 `지에스`보다 먼저 매칭돼야 한다.

**어떤 입력에도 빈 문자열을 반환하지 않는다.** 규칙이 실패하면 항상 원본 `name`으로 되돌아간다.

### 적용 지점

- `app/(public)/amenity/[category]/_components/amenity-card.tsx` — 목록 카드 `h3`
- `app/(public)/amenity/[category]/[id]/page.tsx` — 상세 `h1`, breadcrumb, JSON-LD `name`, meta title
- `lib/amenity/infra.ts` — 아파트 상세의 "주변 생활 인프라" 항목 이름

`splitBrand`는 카테고리 슬러그가 `convenience`일 때만 참으로 넘긴다.

### 검색

`lib/amenity/adapters/{convenience,cafe,mart}.ts`가 지금 `where.name = { contains: f.q }`를 쓴다(각 파일 22행 부근). `name` 또는 `branchName` 중 하나라도 매치하도록 `OR`로 바꾼다. 안 바꾸면 `name='미니스톱'` / `branchName='서울역점'`인 매장이 "서울역점"으로 검색되지 않는다 — 화면에는 `미니스톱 서울역점`으로 보이는데 검색이 안 되는 상태가 된다.

`market.ts`는 `Store`가 아니므로 건드리지 않는다.

## 마이그레이션과 배포 순서

컬럼이 nullable이라 기존 코드와 호환된다. 순서는:

1. 마이그레이션 생성 → **머지 전 수동 `prisma:deploy`** (이 저장소는 배포가 마이그레이션을 적용하지 않는다)
2. 코드 머지 — `branchName`이 전부 null이어도 표시 함수는 `name`만으로 동작한다
3. 재수집 실행 → `branchName` 채워짐

3번 전까지는 현재와 동일하게 보이고, 실행 후 이름이 완성된다. 중간 상태에서 깨지는 화면이 없다.

## 테스트

`displayStoreName`이 순수 함수라 규칙을 유닛 테스트로 전부 덮는다. 실측에서 확인된 실제 값을 픽스처로 쓴다.

- `'씨유켄싱턴리조트'` + `'남원점'` + splitBrand → `'씨유 켄싱턴리조트남원점'`
- `'미니스톱'` + `'서울역점'` + splitBrand → `'미니스톱 서울역점'`
- `'세븐혜화점주'` + `'코리아'` + splitBrand → `'세븐 혜화점'` (노이즈 제거 + `점주`→`점`)
- `'세븐효창공원점'` + `'코리아'` + splitBrand → `'세븐 효창공원점'`
- `'세븐일레븐포이중앙'` + `null` + splitBrand → `'세븐일레븐 포이중앙'`
- `'컴포즈커피서산'` + `'석림점'` + splitBrand=false → `'컴포즈커피서산석림점'`
- 최장 일치: `'세븐일레븐영등포'`가 `'세븐'`이 아니라 `'세븐일레븐'`으로 갈리는지
- 최장 일치: `'지에스25익산'`이 `'지에스'`가 아니라 `'지에스25'`로 갈리는지
- 브랜드 미인식 `'에이원'` → 원본 그대로
- 지점부가 비는 `'씨유'` 단독 → 원본 그대로 (`'씨유 '` 같은 값이 나오면 안 된다)
- `branchName`이 null/빈문자열 → `name` 그대로

카드 SSR 테스트로 목록 렌더를 확인하고, 검색 `OR` 조건은 어댑터 단위 테스트로 확인한다.

4. "서울역점"처럼 `branchName`에만 있는 문자열로 검색이 되는지
