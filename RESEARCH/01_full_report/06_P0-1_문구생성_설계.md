# P0-1 상세 페이지 '데이터 해석형 서술' 생성 로직 & 템플릿 설계

> 목표: 자동 생성이되 **규모화된 콘텐츠 남용(Scaled content abuse)으로 오인되지 않는** 페이지별 고유 서술 텍스트.
> 핵심 원칙: **"필드를 문장으로 바꾸지 말고, 데이터로 판단(비교·평가·맥락)을 만든다."**

---

## 0. 왜 이 설계가 필요한가 (정책 경계선)

구글이 금지하는 것과 허용하는 것의 경계는 명확합니다.

| ❌ 위반 신호 (하면 안 됨) | ✅ 허용 (부가가치) |
|---|---|
| 표의 값을 그대로 문장으로 재서술 ("정원 69명입니다. 현원 57명입니다.") | 값에서 **파생된 판단** ("충원율 83%로 인근 평균보다 높다") |
| 동의어 치환·어순 변경으로 문장 대량 생성(synonym spinning) | **조건 분기 + 실제 수치 비교**로 페이지마다 내용 자체가 다름 |
| 모든 페이지가 동일 문장 골격 | 데이터 값에 따라 **발화되는 문장 자체가 달라짐** |
| 데이터가 없는데도 억지로 채운 문장 | 데이터 부족 시 **서술 생략 + noindex** |

→ 결론: 우리가 만들 것은 **"룰 기반 인사이트 엔진"** 입니다. 문장을 스핀하는 게 아니라, **각 엔티티를 또래 집단(peer group)과 비교해 판단 문장을 조립**합니다. 고유성은 문구가 아니라 **데이터와 비교 결과**에서 나옵니다.

---

## 1. 아키텍처 (3 레이어)

```
[Layer 1] 사전 집계(Precompute)   ── 배치/빌드타임
   지역·반경별 벤치마크 통계를 미리 계산해 저장
   예: region_childcare_stats(충원율 중앙값, 교사당 원아 p50, 정원 분포)

[Layer 2] 인사이트 엔진(Insight Engine) ── 요청/ISR 렌더타임
   엔티티 데이터 + 벤치마크 → 독립 "인사이트 모듈" 여러 개 실행
   각 모듈: (가드 조건 통과 시) 수치·비교가 담긴 1~2문장 생성

[Layer 3] 조립·렌더(Compose & SSR)
   발화된 모듈을 자연스러운 단락으로 결합 → 서버사이드 렌더(HTML에 포함)
```

**중요**: 인사이트에 쓰는 벤치마크(또래 평균/중앙값)는 imjangon이 **이미 보유한 데이터로 계산**합니다. 새 데이터 수집 불필요 — 이것이 "고유한 이점(unique benefit)"의 원천입니다.

## 2. 인사이트 모듈 카탈로그 — 어린이집 상세

각 모듈은 **독립적으로 발화 여부를 판단**합니다(가드 조건). 데이터가 없거나 비교 대상이 부족하면 침묵합니다.

| 모듈 | 입력 | 파생 판단(예) | 가드 조건 |
|---|---|---|---|
| **M1 수요·충원율** | 정원, 현원, 반경 1km 또래 충원율 중앙값 | "충원율 83%, 인근 평균 76%보다 높음 → 수요 견조" | 정원≥1 & 또래 표본≥5 |
| **M2 대기 압력** | 연령별 대기 인원 | "만0세 대기 35명으로 전체 대기의 90% → 영아반 경쟁 치열" | 총대기≥3 |
| **M3 교사당 원아** | 보육교사 수, 현원 | "교사 1인당 원아 약 3.4명(만0세 반 다수 → 영아 집중형)" | 보육교사≥1 & 현원≥1 |
| **M4 유형·규모 성격** | 설립유형, 정원, 지역 정원 분위 | "정원 69명은 지역 민간 어린이집 중 상위 30% 규모" | 지역 표본≥10 |
| **M5 안전·시설** | CCTV, 보육실㎡/정원, 놀이터, 통학차량 | "아동 1인당 보육공간 약 2.7㎡, 통학차량 운영" | 최소 2개 필드 존재 |
| **M6 생활권 접근성** | 최근접 역·도보분, 반경 500m 인프라 수 | "도보 16분 상현역, 반경 500m 카페8·병원2 → 인프라 양호" | 역 정보 또는 인프라≥3 |
| **M7 주변 시세 맥락** | 반경 1km 아파트 실거래 min~max | "도보권 아파트 실거래 9억~16억대 분포" | 아파트 표본≥3 |

**설계 포인트**
- 각 모듈은 **수치 + 비교/평가어**를 반드시 포함(그냥 수치 나열 금지).
- 발화 모듈 수가 데이터에 따라 3~7개로 **가변** → 페이지 길이·구성이 자연히 달라짐.
- M1·M4는 **또래 벤치마크 비교**가 핵심 — 표에 없는 정보를 생산하므로 부가가치가 가장 큼.

## 3. 변형(Uniqueness) 전략 — spinning과의 결정적 차이

고유성은 **3개 축**에서 나오며, 어느 것도 동의어 스핀이 아닙니다.

1. **데이터 값 자체** — 충원율·대기·비율·시세가 엔티티마다 다름 → 문장의 **숫자와 결론이 다름**.
2. **발화 모듈 조합** — 어떤 모듈이 발화되는지가 데이터 조건에 따라 달라짐 → **단락 구성이 다름**.
3. **판단 구간(bucket)별 서술 분기** — 각 모듈은 값 구간에 따라 **다른 평가 문장**을 선택.

**판단 구간 분기 예 (M1 충원율)**
```
diff = 해당원 충원율 − 지역 또래 충원율 중앙값
 diff ≥ +15%p → "인근 대비 수요가 뚜렷하게 높은 편"
 +5 ~ +15%p  → "인근 평균을 웃도는 수요"
 −5 ~ +5%p   → "인근과 비슷한 수요 수준"
 < −5%p       → "정원 여유가 있는 편(입소 문의 시 자리 가능성)"
```
→ 같은 슬롯이라도 **데이터가 다르면 결론 문장 자체가 달라짐**. 이것이 정책상 안전한 변형입니다.

**금지(절대)**
- 문장 뜻이 같은데 표현만 바꾼 변형(예: "높습니다"/"높은 편입니다"/"상당합니다"를 랜덤 로테이션) — synonym spinning으로 간주될 수 있음. 변형은 **의미(데이터 결론)가 달라질 때만** 한다.
- 무작위(seed) 문구 셔플로 다양성 흉내내기 금지.

## 4. 실제 코드 (TypeScript / Next.js)

### 4.1 사전 집계 (Layer 1) — 지역·반경 벤치마크

```ts
// scripts/precompute-childcare-stats.ts  (배치: 데이터 갱신 시 1회)
type ChildcareRow = {
  id: string; sido: string; sigungu: string; lat: number; lng: number;
  type: '국공립' | '민간' | '가정' | '직장' | '사회복지법인' | string;
  capacity: number; current: number; teachers: number;
};

// 지역(시군구) × 설립유형별 벤치마크
export function buildRegionStats(rows: ChildcareRow[]) {
  const groups = new Map<string, ChildcareRow[]>();
  for (const r of rows) {
    const key = `${r.sigungu}::${r.type}`;
    (groups.get(key) ?? groups.set(key, []).get(key)!).push(r);
  }
  const stats: Record<string, {
    n: number; occMedian: number; capP70: number; teacherRatioP50: number;
  }> = {};
  for (const [key, g] of groups) {
    const occ = g.filter(r => r.capacity > 0).map(r => r.current / r.capacity);
    const caps = g.map(r => r.capacity);
    const ratios = g.filter(r => r.teachers > 0).map(r => r.current / r.teachers);
    stats[key] = {
      n: g.length,
      occMedian: median(occ),
      capP70: percentile(caps, 0.7),
      teacherRatioP50: median(ratios),
    };
  }
  return stats; // JSON으로 저장 → 렌더타임에 로드
}

const median = (a: number[]) => percentile(a, 0.5);
function percentile(a: number[], p: number) {
  if (!a.length) return NaN;
  const s = [...a].sort((x, y) => x - y);
  const i = Math.min(s.length - 1, Math.floor(p * (s.length - 1)));
  return s[i];
}
```

> 반경 1km 또래 통계가 필요하면 좌표 기반 그리드(geohash) 버킷으로 사전 계산하거나, 이미 각 상세 페이지가 계산하는 "근처 어린이집 1km" 목록을 재활용해 즉석 집계해도 됩니다.

### 4.2 인사이트 엔진 (Layer 2) — 모듈 + 조립

```ts
// lib/insights/childcare.ts
type Nearby = { name: string; distanceM: number; occ?: number };
type ChildcareDetail = {
  name: string; type: string; capacity: number; current: number;
  teachers: number; teacherRole?: { boyuk?: number };
  cctv?: number; roomArea?: number; rooms?: number; hasBus?: boolean;
  waitByAge?: { age: string; count: number }[];
  nearestStation?: { line: string; name: string; walkMin: number; distanceKm: number };
  infra500m?: { cafe?: number; conv?: number; hospital?: number; park?: number };
  nearbyAptPriceEok?: number[];      // 반경 1km 아파트 실거래(억)
  peerOccMedian?: number;            // 벤치마크(사전집계)
  peerCapP70?: number;
};

type Insight = { key: string; weight: number; text: string };

// 유틸: 데이터 결론이 바뀌는 '구간 분기'만 사용 (synonym 로테이션 아님)
const pct = (x: number) => Math.round(x * 100);

function m1_demand(d: ChildcareDetail): Insight | null {
  if (!d.capacity || d.current == null) return null;
  const occ = d.current / d.capacity;
  const base = `${d.type} 어린이집으로 정원 ${d.capacity}명 대비 현원 ${d.current}명, 충원율 ${pct(occ)}%입니다`;
  if (d.peerOccMedian == null) return { key: 'demand', weight: 9, text: base + '.' };
  const diff = pct(occ) - pct(d.peerOccMedian);
  const judge =
    diff >= 15 ? `인근 동일 유형 어린이집(중앙값 ${pct(d.peerOccMedian)}%)보다 충원율이 뚜렷하게 높아 수요가 견조한 편입니다`
    : diff >= 5 ? `인근 평균(${pct(d.peerOccMedian)}%)을 웃도는 충원율로 수요가 있는 편입니다`
    : diff > -5 ? `인근 평균(${pct(d.peerOccMedian)}%)과 비슷한 수준입니다`
    : `인근 평균(${pct(d.peerOccMedian)}%)보다 정원 여유가 있어 입소 문의 시 자리가 있을 가능성이 있습니다`;
  return { key: 'demand', weight: 10, text: `${base}. ${judge}.` };
}

function m2_wait(d: ChildcareDetail): Insight | null {
  const w = d.waitByAge?.filter(x => x.count > 0) ?? [];
  const total = w.reduce((s, x) => s + x.count, 0);
  if (total < 3) return null;
  const top = w.sort((a, b) => b.count - a.count)[0];
  const share = pct(top.count / total);
  const judge = share >= 60
    ? `대기 ${total}명 중 ${top.age} 대기가 ${top.count}명(약 ${share}%)으로, ${top.age} 반 입소 경쟁이 특히 치열합니다`
    : `총 ${total}명이 입소 대기 중이며 ${top.age} 대기가 가장 많습니다`;
  return { key: 'wait', weight: 8, text: judge + '.' };
}

function m3_teacherRatio(d: ChildcareDetail): Insight | null {
  const t = d.teacherRole?.boyuk ?? d.teachers;
  if (!t || !d.current) return null;
  const ratio = d.current / t;
  return { key: 'ratio', weight: 6,
    text: `보육교사 ${t}명이 근무해 교사 1인당 원아 약 ${ratio.toFixed(1)}명 수준입니다.` };
}

function m5_facility(d: ChildcareDetail): Insight | null {
  const parts: string[] = [];
  if (d.roomArea && d.current) parts.push(`원아 1인당 보육실 면적 약 ${(d.roomArea / d.current).toFixed(1)}㎡`);
  if (d.cctv) parts.push(`CCTV ${d.cctv}대`);
  if (d.hasBus) parts.push('통학차량 운영');
  if (parts.length < 2) return null;
  return { key: 'facility', weight: 4, text: parts.join(', ') + ' 등을 갖췄습니다.' };
}

function m6_access(d: ChildcareDetail): Insight | null {
  const s = d.nearestStation, i = d.infra500m;
  const seg: string[] = [];
  if (s) seg.push(`가장 가까운 지하철역은 ${s.line} ${s.name}으로 도보 약 ${s.walkMin}분(${s.distanceKm}km)`);
  const infra = i ? [
    i.cafe && `카페 ${i.cafe}곳`, i.conv && `편의점 ${i.conv}곳`,
    i.hospital && `병원 ${i.hospital}곳`, i.park && `공원 ${i.park}곳`,
  ].filter(Boolean) : [];
  if (infra.length >= 2) {
    const dense = infra.length >= 3 ? '영유아 동반 생활 편의가 양호한 편입니다' : '기본 생활 편의를 갖췄습니다';
    seg.push(`반경 500m 안에 ${infra.join('·')}이 있어 ${dense}`);
  }
  if (!seg.length) return null;
  return { key: 'access', weight: 5, text: seg.join('이며, ') + '.' };
}

function m7_price(d: ChildcareDetail): Insight | null {
  const p = (d.nearbyAptPriceEok ?? []).filter(x => x > 0);
  if (p.length < 3) return null;
  const lo = Math.min(...p), hi = Math.max(...p);
  return { key: 'price', weight: 3,
    text: `도보권 아파트 실거래가는 약 ${lo}억~${hi}억 원대에 분포합니다.` };
}

export function buildChildcareNarrative(d: ChildcareDetail): string | null {
  const mods = [m1_demand, m2_wait, m3_teacherRatio, m5_facility, m6_access, m7_price]
    .map(fn => fn(d)).filter(Boolean) as Insight[];
  // 가드: 최소 3개 모듈 & M1(수요) 필수 → 미달이면 서술 생략(→ noindex 대상)
  if (mods.length < 3 || !mods.some(m => m.key === 'demand')) return null;
  const ordered = mods.sort((a, b) => b.weight - a.weight);
  // 첫 문장은 원 이름으로 시작(고유 명사 → 고유성↑)
  return `${d.name}은(는) ${ordered.map(m => m.text).join(' ')}`;
}
```

## 5. 워크드 예시 — 광교샛별어린이집 (실제 스크랩 데이터)

**입력 데이터**: 민간 / 정원 69·현원 57(83%) / 보육교사 17 / CCTV 8 / 보육실 6실 187㎡ / 통학차량 O / 대기 총 39(만0세 35·만1세 2·만2세 2) / 상현역 신분당선 도보16분(1.1km) / 반경500m 카페8·편의4·병원2 / 도보권 아파트 9.05~16억 / (가정 벤치마크: 수원 영통 민간 충원율 중앙값 76%)

**생성 결과 (예)**
> **광교샛별어린이집**은(는) 민간 어린이집으로 정원 69명 대비 현원 57명, 충원율 83%입니다. 인근 동일 유형 어린이집(중앙값 76%)을 웃도는 충원율로 수요가 있는 편입니다. 대기 39명 중 만 0세 대기가 35명(약 90%)으로, 만 0세 반 입소 경쟁이 특히 치열합니다. 가장 가까운 지하철역은 신분당선 상현역으로 도보 약 16분(1.1km)이며, 반경 500m 안에 카페 8곳·편의점 4곳·병원 2곳이 있어 영유아 동반 생활 편의가 양호한 편입니다. 보육교사 17명이 근무해 교사 1인당 원아 약 3.4명 수준입니다. 원아 1인당 보육실 면적 약 3.3㎡, CCTV 8대, 통학차량 운영 등을 갖췄습니다. 도보권 아파트 실거래가는 약 9억~16억 원대에 분포합니다.

**대비 예시(정원 여유 + 데이터 적은 가정 어린이집)** — 같은 골격이 아니라 발화 모듈·결론이 달라짐:
> **○○가정어린이집**은(는) 가정 어린이집으로 정원 20명 대비 현원 11명, 충원율 55%입니다. 인근 평균(76%)보다 정원 여유가 있어 입소 문의 시 자리가 있을 가능성이 있습니다. 보육교사 3명이 근무해 교사 1인당 원아 약 3.7명 수준입니다. (대기·역·시세 데이터 부족 → 해당 문장 생략)

→ 두 페이지는 **문장 수·구성·결론이 모두 다름**. 데이터가 다르기 때문이지 문구를 스핀했기 때문이 아님.

## 6. 다른 페이지 유형으로 확장 (요약)

| 페이지 | 스타 모듈(비교·판단) | 파생 판단 예 |
|---|---|---|
| **아파트 상세** | 최근 실거래 추세, 생활권 대비 가격 위치 | "최근 3개월 3건 거래, 전 분기 대비 +4%. 동일 생활권 중위가 대비 상위 20%" |
| **병원/약국** | 진료과목 밀도, 야간·공휴일 운영 | "반경 1km 내 동일 진료과 5곳 중 유일하게 토요 진료" |
| **학교** | 학급당 학생수, 지역 대비 | "학급당 24명으로 관내 평균(27명)보다 여유" |

공통 규칙은 동일: **표에 없는 '비교·추세·순위'를 데이터로 계산**해 문장화.

## 7. QA·측정·롤아웃 체크리스트

**출고 전 게이트**
- [ ] 각 서술은 **최소 1개 이상 비교/파생 판단**(또래 대비, 비율, 추세, 순위)을 포함하는가? (단순 필드 재서술 0건)
- [ ] 서술 텍스트가 **JS 없이 HTML(SSR)** 에 렌더되는가? (view-source로 확인)
- [ ] 데이터 부족 페이지는 서술 생략 + **noindex** 되는가?

**고유성 측정 (spinning 방지 검증)**
- [ ] 전체 상세 페이지 표본 500개에서 **5-shingle Jaccard 유사도 중앙값 < 0.3** (문장 골격 복제 아님) 확인.
- [ ] 동일 문장(정확 일치)이 N개 이상 페이지에 반복되면 경보 → 해당 모듈의 분기 세분화.

**롤아웃**
1. 어린이집 카테고리에 먼저 적용(대표 20개 육안 검수) → 2. 아파트·병원 확대 → 3. 2~4주 색인 반영 관찰 후 재신청.
- 지표: `색인 페이지 중 서술 보유 비율`, `평균 페이지 텍스트 길이`, `Search Console 색인/노출 추이`.

## 8. 절대 하지 말 것 (요약)

1. 동의어·어순만 바꾼 문장 대량 생성(synonym spinning) — 규모화 남용 신호.
2. 데이터 없는데 억지 문장 채우기 — 침묵하고 noindex가 정답.
3. 모든 페이지 동일 문장 골격 유지 — 반드시 **데이터 구간 분기**로 결론이 갈리게.
4. 클라이언트 전용 렌더(빈 SPA) — 반드시 SSR.

→ 한 문장 요약: **"페이지마다 다른 것은 문구가 아니라 데이터에서 나온 판단이어야 한다."**
