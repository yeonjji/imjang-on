# 전체 카테고리 통합 설계 — P0-1(해석 프로즈) + JSON-LD(출처 스키마)

> 앞선 06(P0-1)·07(JSON-LD)은 어린이집 중심이었다. 이 문서는 **imjangon의 모든 상세 카테고리**를 하나의 프레임워크로 묶는다.
> 원칙 동일: **"필드를 문장으로 바꾸지 말고 데이터로 판단을 만든다"** + **"출처·신선도를 구조화 데이터로 선언한다"**.
> 출처 기관은 **imjangon이 각 페이지 하단에 이미 표기한 값**을 그대로 사용(재추정 아님).

## 1. 카테고리 인벤토리 (전수)

| 카테고리 | 라우트(예) | 엔티티 schema.org 타입 | 출처기관(imjangon 표기) | 데이터 성격 |
|---|---|---|---|---|
| 아파트 | `/apt/{id}` | `ApartmentComplex` | 국토교통부 실거래가 | 실거래·시세·연식·세대 |
| 오피스텔 | `/officetel/{id}` | `ApartmentComplex`/`Residence` | 국토교통부 | 실거래·시세 |
| 다세대·빌라 | `/villa/{id}` | `ApartmentComplex`/`Residence` | 국토교통부 | 실거래·시세 |
| 청약 | `/subscription/{id}` | `ApartmentComplex` + `offers` | 한국부동산원·LH | 공급세대·일정·지역 |
| 어린이집 | `/childcare/{r}/{id}` | `ChildCare` | 보건복지부(한국사회보장정보원) | 정원·현원·교직원·시설 |
| 학교 | `/school/{id}` | `School`(EducationalOrganization) | 교육부(학교알리미) | 학급·학생·교원·배정 |
| 병원·의원 | `/medical/hospital/{…}` | `Hospital`/`MedicalClinic` | 건강보험심사평가원 | 진료과목·운영시간 |
| 약국 | `/medical/pharmacy/{…}` | `Pharmacy` | 건강보험심사평가원 | 운영시간·야간여부 |
| 공원 | `/urban/park/{id}` | `Park` | 행정안전부 | 유형·면적 |
| 주차장 | `/urban/parking/{id}` | `ParkingFacility` | 행정안전부 | 공영여부·면수 |
| 전기차 충전소 | `/urban/charger/{id}` | `Place`(+속성) ※EV 전용타입 없음 | 한국환경공단 | 급속/완속·기수 |
| 전통시장 | `/amenity/market/{id}` | `ShoppingCenter` | 소상공인시장진흥공단 | 점포·위치 |
| 편의점/마트 | `/amenity/mart/{id}` | `ConvenienceStore`/`GroceryStore` | 소상공인시장진흥공단 | 업종·위치 |
| 카페 | `/amenity/cafe/{id}` | `CafeOrCoffeeShop` | 소상공인시장진흥공단 | 업종·위치 |
| 지하철역 | `/subwayStation/{id}` | `SubwayStation` | 국가철도공단 | 노선·환승 |
| 지역별 시세(허브) | `/region/{code}` | `WebPage`/`Dataset` | 국토교통부 | 집계·분석(에디토리얼 후보) |

## 2. 공통 프레임워크 (전 카테고리 공유)

### 2.1 인사이트 모듈 매트릭스

모듈은 **공통 6종**을 재사용하고, 카테고리마다 발화 여부·지표만 바뀐다. (스핀 아님 — 데이터 결론이 다름)

| 모듈 | 정의(파생 판단) | 적용 카테고리 |
|---|---|---|
| **P (Peer)** 또래 비교 | 동종 시설의 지역/반경 벤치마크 대비 위치 | 어린이집(충원율)·학교(학급당 학생)·아파트(가격/연식)·병원(진료과 수) |
| **D (Density)** 밀도·경쟁 | 반경 내 동종 시설 수, 희소/과밀 판단 | 병원·약국·카페·편의점·시장·충전소·주차장 |
| **A (Access)** 접근성 | 최근접 지하철·도보분, 반경 인프라 수 | 전 카테고리 공통 |
| **C (Price Context)** 시세 맥락 | 반경 아파트 실거래 range로 '동네 가격대' 제시 | 전 카테고리 공통(입지 성격) |
| **S (Status)** 운영·신선도 | 영업상태·운영시간·야간/공휴일·기준일 | 병원·약국·시장·편의시설·주차장 |
| **T (Trend/Time)** 추세·시점 | 실거래 추세, 청약 D-day·일정, 연식 | 아파트·오피스텔·빌라·청약 |

**카테고리별 스타 모듈**(가장 부가가치 큰 것):

| 카테고리 | 스타 모듈 |
|---|---|
| 아파트/오피스텔/빌라 | **T**(추세) + **P**(생활권 대비 가격) + A + C |
| 청약 | **T**(일정 D-day) + 공급 규모 + A |
| 어린이집 | **P**(충원율) + 대기압력 + A |
| 학교 | **P**(학급당 학생수) + 배정·통학 + C |
| 병원·의원 | **D**(진료과 희소성) + **S**(야간·주말) + A |
| 약국 | **S**(심야/공휴일) + **D** + A |
| 공원/주차장/충전소 | **D**(밀도) + 규모(면적/면수/기수) + A |
| 시장/편의/카페 | **A** + **C** + **S**(영업상태) |
| 지하철역 | 노선·환승 + **D**(역세권 인프라) |

### 2.2 공통 가드(모든 카테고리)
- 발화 모듈 **< 3개** 또는 스타 모듈 미발화 → **서술 생략 + noindex**(아래 3장).
- 각 서술은 **최소 1개 비교/파생 판단** 필수(단순 필드 재서술 0건).
- **SSR**로 출력(imjangon은 이미 SSR 확인됨 → 유지).

## 3. noindex 정책 (카테고리별 얇은 페이지 정리)

전 카테고리 공통 규칙 — "데이터 밀도"로 색인 여부 결정:

| 판정 | 처리 |
|---|---|
| 핵심 데이터 충분 + 서술 3모듈↑ | **index** (알짜 페이지) |
| 데이터 희박(폐업/정보없음/좌표없음) | **noindex** + sitemap 제외 |
| 순수 목록 페이지네이션 셸(`?page=`) | **noindex, follow** |
| 파라미터 중복 URL | `canonical` 통합 |

특히 **편의점/카페/음식점 등 초대량·초경량 카테고리**는 기본 noindex로 두고, **주변 인프라로서 다른 페이지에 링크로만 노출**하는 편이 사이트 평균 품질에 유리(개별 색인은 thin 위험).

## 3.5 보일러플레이트 비율 · 크롤 예산 (전 카테고리 공통 리스크)

해석 프로즈·noindex와 별개로, **반복 블록(boilerplate) 비중**이 별도 리스크다. 모든 상세 페이지가 "주변 아파트·근처 동종 시설·생활 인프라·최신 브리핑" 블록을 공유하므로, 페이지 고유 콘텐츠가 적으면 **템플릿 대비 고유 텍스트 비율**이 낮아져 thin으로 보이기 쉽다.

- **고유:보일러플레이트 목표** — 각 색인 페이지에서 **고유 콘텐츠(해석 프로즈 + 엔티티 고유 데이터)가 페이지 텍스트의 30%+**가 되도록. 미달이면 해석 프로즈를 늘리거나 noindex.
- **반복 블록 다이어트** — 주변 목록은 개수를 절제(예: 상위 5개)하고, 나머지는 "더보기"로 지연 로드해 초기 HTML의 boilerplate를 줄인다.
- **크롤 예산 관리** — 수만 페이지 규모이므로: ① `sitemap.xml`에는 **index 대상(알짜)만**, ② noindex/파라미터 URL은 sitemap 제외, ③ 저가치 대량 카테고리(편의/카페/음식점)는 크롤 유입을 제한해 크롤러가 **알짜 페이지에 집중**하도록 한다.
- **측정** — 색인 페이지 표본의 `고유텍스트/전체텍스트` 비율, 페이지 간 `5-shingle Jaccard`(중앙값 < 0.3)로 boilerplate 과다·복제 여부를 정량 점검.

### 4.1 범용 JSON-LD 빌더 (모든 카테고리 공용)

```ts
// lib/jsonld/build.ts
import { CATEGORIES } from '../registry/categories';

export function buildJsonLd(catKey: string, e: {
  url: string; name: string; lat?: number; lng?: number;
  address?: { region?: string; locality?: string; street?: string };
  tel?: string; dateModified?: string; datePublished?: string; ogImage?: string;
  props?: Array<{ name: string; value: unknown; unit?: string }>;
}) {
  const c = CATEGORIES[catKey];
  const page = `${e.url}#webpage`, ent = `${e.url}#entity`, ds = `${e.url}#dataset`, src = `${e.url}#src`;
  const P = (p:{name:string;value:unknown;unit?:string}) =>
    ({ '@type':'PropertyValue', name:p.name, value:p.value, ...(p.unit?{unitText:p.unit}:{}) });
  return [
    { '@context':'https://schema.org','@type':'Organization','@id':'https://imjangon.co.kr/#org',
      name:'임장ON', url:'https://imjangon.co.kr', logo:'https://imjangon.co.kr/icon-512.png' },
    { '@context':'https://schema.org','@type':'WebPage','@id':page, url:e.url, name:`${e.name} | 임장ON`,
      inLanguage:'ko-KR', mainEntity:{'@id':ent}, isBasedOn:{'@id':ds}, sourceOrganization:{'@id':src}, license:c.license,
      ...(e.ogImage?{primaryImageOfPage:e.ogImage}:{}),
      ...(e.datePublished?{datePublished:e.datePublished}:{}),
      ...(e.dateModified?{dateModified:e.dateModified}:{}) },
    { '@context':'https://schema.org','@type':c.source.type ?? 'Organization','@id':src,
      name:c.source.name, url:c.source.url },
    { '@context':'https://schema.org','@type':'Dataset','@id':ds, name:c.dataset.name, url:c.dataset.url,
      creator:{'@id':src}, license:c.license,
      ...(c.dataset.datasetId?{sameAs:`https://www.data.go.kr/data/${c.dataset.datasetId}/openapi.do`}:{}) },
    { '@context':'https://schema.org','@type':c.schemaType,'@id':ent, name:e.name, url:e.url,
      ...(e.tel?{telephone:e.tel}:{}),
      ...(e.address?{address:{'@type':'PostalAddress',addressCountry:'KR',
        ...(e.address.region?{addressRegion:e.address.region}:{}),
        ...(e.address.locality?{addressLocality:e.address.locality}:{}),
        ...(e.address.street?{streetAddress:e.address.street}:{})}}:{}),
      ...(e.lat&&e.lng?{geo:{'@type':'GeoCoordinates',latitude:e.lat,longitude:e.lng}}:{}),
      ...(e.props?.length?{additionalProperty:e.props.map(P)}:{}),
      // 출처(isBasedOn/sourceOrganization/license)는 WebPage에만. 엔티티(Place)는 mainEntityOfPage로만 연결.
      mainEntityOfPage:{'@id':page} },
  ];
}
```

→ 카테고리별 `schemaType`·출처는 레지스트리에서 자동 주입. `props`만 페이지 데이터로 채우면 끝.

## 5. 카테고리별 예시 서술문 (P0-1 결과 샘플)

각 1문단 예시(실제로는 데이터·벤치마크에 따라 문장/결론이 달라짐):

- **아파트**: "○○아파트는 2013년 준공 998세대 단지로, 최근 3개월 매매 5건이 신고돼 직전 분기보다 거래가 활발합니다. 최근 실거래 9.0억은 동일 생활권(수원 영통) 중위가 대비 상위 20% 수준이며, 도보 8분 거리 신분당선 상현역과 반경 500m 인프라가 뒷받침합니다."
- **청약**: "○○단지 청약은 일반공급 320세대 규모로 오늘 기준 접수 D-1입니다. 인근 최근 분양 대비 공급 세대가 많은 편이며, 동일 자치구 최근 실거래가는 6억~9억대에 분포합니다."
- **학교**: "○○초등학교는 학급당 평균 24명으로 관내 평균(27명)보다 여유가 있고, 최근 3년 학생수는 완만한 감소세입니다. 도보 통학권 아파트 실거래가는 5억~7억대입니다."
- **병원**: "○○이비인후과는 반경 1km 내 동일 진료과 5곳 중 유일하게 토요일 오후 진료를 운영합니다. 가장 가까운 약국은 도보 2분 거리입니다."
- **약국**: "○○약국은 인근 4개 약국 중 유일하게 심야(밤 12시까지) 운영으로, 공휴일 응급 시 접근성이 높습니다."
- **공원**: "○○근린공원은 116,170㎡ 규모로 반경 1km 공원 10곳 중 두 번째로 넓으며, 도보 9분 거리입니다."
- **충전소**: "○○충전소는 급속 7기를 갖춰 반경 1km 충전 인프라(총 3곳) 중 급속 비중이 가장 높습니다."
- **전통시장**: "○○시장은 반경 2km 유일한 전통시장으로, 도보 12분·주변 아파트 4억~6억대 생활권의 핵심 상권입니다."
- **지하철역**: "○○역은 2개 노선 환승역으로, 반경 500m에 카페 22곳·병원 8곳이 밀집한 역세권입니다."

> 편의점/카페/음식점은 개별 색인 대상이 아니라(3장) 위 시설들의 **주변 인프라 밀도 근거**로 소비.

## 6. 우선순위 (전 카테고리 롤아웃)

색인 페이지 수 × 검색수요 × 부가가치 잠재력 기준:

| 순위 | 카테고리 | 이유 |
|---|---|---|
| **1** | 아파트/오피스텔/빌라 | 검색수요 최상, 추세·시세 해석 부가가치 큼 |
| **2** | 어린이집·학교 | 학부모 수요 높음, 또래 비교가 강력 |
| **3** | 병원·약국 | 야간·주말·진료과 희소성 해석이 실질 유용 |
| **4** | 지하철역·공원(허브형) | 역세권·생활권 앵커 페이지 |
| **5** | 청약 | 일정성 콘텐츠(신선도↑) |
| **보류** | 편의/카페/음식점·초경량 | 기본 noindex, 인프라 근거로만 활용 |

각 단계: 대표 20개 육안 검수 → JSON-LD Rich Results Test 통과 → 2~4주 색인 관찰.

## 7. 요약

- **하나의 카테고리 레지스트리**가 프로즈 모듈·JSON-LD 출처스키마·noindex 임계치를 전 카테고리에 걸쳐 구동한다.
- 공통 인사이트 6모듈(P/D/A/C/S/T)을 재사용하되 **카테고리마다 스타 모듈·지표만 다름** → 스핀 아님.
- 초대량·초경량 카테고리(편의/카페/음식점)는 **개별 색인 대신 인프라 근거로 소비**해 사이트 평균 품질을 지킨다.
- imjangon은 SSR·엔티티 스키마가 이미 좋으니, **전 카테고리에 (출처 스키마 + 해석 프로즈)만 레지스트리 기반으로 일괄 적용**하면 된다.
