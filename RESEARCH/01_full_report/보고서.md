# imjangon.co.kr 애드센스 'thin content' 거절 원인 분석 및 개선 보고서

**작성일**: 2026-07-01
**대상**: imjangon.co.kr(임장ON) — 공공데이터 기반 부동산 실거래가·생활권 통합 플랫폼
**방법론**: Firecrawl로 대상 사이트 구조·페이지 크롤링 → 구글 공식 정책 문서 및 동일 유형 거절 사례 리서치 → 교차검증
**검증**: 핵심 정책 주장 2건은 구글 1차 공식 문서(A급)로 검증 완료. 커뮤니티 수치 기준은 '비공식 통설'로 명시 구분.

## 1. 개요 — 무엇을 분석했나

이 보고서는 두 가지 질문에 답합니다.

1. 구글 애드센스는 왜 사이트를 **'가치 없는 콘텐츠(low-value content)' / '얇은 콘텐츠(thin content)'** 로 거절하는가?
2. 그 기준에 비추어 **imjangon.co.kr은 구체적으로 무엇이 부족하며, 어떻게 고쳐야 하는가?**

분석을 위해 실제로 크롤링한 imjangon.co.kr 페이지는 다음과 같습니다.

- 홈페이지(`/`) — 실거래가·청약·생활권 통합 대시보드
- 어린이집 상세(`/childcare/41110/10120` 광교샛별어린이집) — 대표적 '상세 데이터 페이지'
- 가이드 목록(`/guide`)과 가이드 원문(`/guide/실거래가어떻게읽고활용할까`)
- 사이트맵 구조(`/sitemaps/0`~`/sitemaps/22`, `/childcare/{지역코드}/{id}` 대량 페이지)

그리고 구글 측 기준으로는 **구글 검색 스팸 정책(A급 공식 문서)** 을, 동종 사례로는 **거의 동일한 한국 서비스가 같은 사유로 거절된 애드센스 커뮤니티 스레드** 를 확보했습니다.

## 2. 애드센스 'thin content' 거절 메커니즘 — 원인 규명

### 2.1 '가치 없는 콘텐츠'는 사실상 신규 사이트 포괄 거절 코드

애드센스의 사이트 심사는 **정해진 기준에 따른 자동화 시스템(로봇)** 이 1차로 수행하며, 거절 통지는 구체적 지적 없이 "low-value content"라는 포괄 사유만 제시합니다. 실제 애드센스 커뮤니티에서 다이아몬드 등급 전문가도 *"사이트 심사는 로봇이 정해진 기준에 따라 합니다"* 라고 답합니다(애드센스 커뮤니티 스레드, support.google.com). 실무자들은 이 사유가 **콘텐츠가 실제로 나빠서가 아니라, 봇이 '신뢰 신호'를 충분히 못 읽었을 때 나오는 catch-all 코드**라고 정리합니다(Toolpod, 2025-12).

즉 문제를 **"내 콘텐츠가 나쁜가?"** 가 아니라 **"봇이 내 페이지에서 고유한 가치를 텍스트로 읽어낼 수 있는가?"** 로 재정의해야 합니다. 이 관점이 imjangon 진단의 핵심 축입니다.

### 2.2 구글이 명시적으로 금지하는 패턴 (A급 공식 근거)

구글 검색 스팸 정책 문서는 다음을 **명확한 정책 위반**으로 규정합니다(developers.google.com, 2026-05-15 갱신). 애드센스 게시자 정책도 이 검색 품질 기준을 준용합니다.

- **규모화된 콘텐츠 남용(Scaled content abuse)** — *"검색 순위 조작을 주목적으로, 사용자에게 가치를 거의 주지 않는 비독창적 콘텐츠를 대량으로 만드는 것. 생성 방식과 무관."* 예시에 **"피드·검색결과·기타 콘텐츠를 스크래핑해 다수 페이지를 생성(동의어 치환·번역 등 자동 변환 포함), 사용자 가치가 적은 경우"**, **"서로 다른 페이지의 콘텐츠를 짜깁기·결합하되 가치를 더하지 않는 경우"** 가 포함됨. → **[검증됨, A급]**
- **스크래핑(Scraping)** — *"다른 사이트의 콘텐츠 피드를 사용자에게 어떤 고유한 이점도 제공하지 않고 재현하는 것"*, *"영상·이미지·기타 미디어를 모아 보여주기만 하고 실질적 부가가치가 없는 사이트"* 는 위반. → **[검증됨, A급]**
- **얇은 제휴/도어웨이(Thin affiliation, Doorway)** — 원본을 거의 그대로 복제한 "쿠키커터/템플릿" 페이지가 사이트 내·외에 대량 복제되면 사용자에게 불쾌한 경험 → 위반.

> **중요한 균형점**: 구글은 **집계(aggregation) 자체를 금지하지 않습니다.** 같은 문서가 "좋은 제휴/집계 사이트는 **가격 정보·원본 리뷰·엄정한 테스트와 평점·카테고리 탐색·상품 비교 등 실질적 가치를 더한다**"고 명시합니다. 결정적 차이는 **'원본 데이터에 사이트만의 고유한 해석·비교·편집을 텍스트로 더했는가'** 입니다. imjangon의 생존 전략은 바로 이 지점에 있습니다.

### 2.3 원본 콘텐츠의 '양'에 대한 통설 (비공식 — 참고용)

애드센스 커뮤니티와 실무 블로그에서는 다음 수치가 반복 언급됩니다. **단, 이는 구글이 공식화한 수치가 아니라 Product Expert·실무자들의 경험적 통설이며, 이보다 적은 글로 승인된 사례도 존재합니다.**

- 대략 **20~30편** 이상의 독창적 글, **최소 1~3개월** 운영 이력(애드센스 커뮤니티 스레드 다수).
- 각 글 **800~1,200자 이상**의 깊이 있는 원문, 명확한 주제 집중(Medium, 2026-02).
- **원본·직접 작성 텍스트**(AI 자동 생성 대량 텍스트 지양), 규칙적 게시.
- 기본기: **About·개인정보처리방침·연락처** 페이지는 필수 table stakes(Toolpod / Medium).

이 수치는 "정답"이 아니라 "봇이 신뢰 신호를 읽기 시작하는 대략적 임계치"로 이해하는 것이 안전합니다.

### 2.4 신규 사이트 특유의 비-콘텐츠 요인

실무 관찰에 따르면 콘텐츠와 무관하게 작용하는 요인도 있습니다(Toolpod, 2025-12).

- **사이트 연령**: 몇 주~몇 달 된 사이트는 콘텐츠와 무관하게 자주 거절.
- **트래픽 신호**: 이미 방문자가 있는 사이트를 선호(‘가치 먼저 증명’ 요구 — 닭·달걀 문제).
- **도구/데이터형 사이트에 대한 가중 심사**: 광고 노출만 목적인 얇은 유틸리티·데이터 사이트가 워낙 많아, 정당한 사이트도 더 엄격히 봄. → **imjangon처럼 데이터 위주 사이트가 정확히 이 범주의 의심을 받습니다.**

## 3. imjangon.co.kr 진단 — 무엇이, 왜 부족한가

### 3.1 사이트 구조 실측 결과

크롤링으로 확인한 imjangon의 페이지 유형은 두 층으로 뚜렷이 나뉩니다.

**(A) 대량 자동 생성 '데이터 상세' 페이지 — 사이트의 절대 다수**

`/childcare/{지역코드}/{id}` 형태만으로도 사이트맵상 수백~수천 개가 확인되며, 아파트(`/apt`)·오피스텔·다세대·병원(`/medical`)·학교(`/school`)·공원·주차장·충전소·시장·카페 등까지 합치면 **수만 개 규모**입니다(홈 표기: 실거래 735.7만+·단지 27.3만+·생활편의 58만+).

대표 페이지인 광교샛별어린이집(`/childcare/41110/10120`)의 실제 구성은 다음과 같았습니다.

- 기본 정보(주소·전화·인가일·대표자 등) — **표**
- 시설(보육실·놀이터·CCTV·교직원) — **수치 카드**
- 연령별 현황 / 입소대기 / 교직원 근속 — **표·목록**
- 네이버 지도 임베드, 주변 아파트 실거래가(반경 1km) 목록, 근처 어린이집 목록, 주변 생활 인프라 목록, 최신 브리핑 링크

**→ 독창적 서술형 문장(원문 텍스트)은 사실상 0.** 페이지 전체가 공공데이터(보건복지부·국토교통부 등)를 표와 목록으로 재배치한 것입니다. 사람에겐 편리하지만, **크롤러가 읽는 "고유한 원본 텍스트"는 거의 없습니다.** 이것이 구글 정책의 '피드를 고유 이점 없이 재현(스크래핑)' 및 '가치 부가 없는 짜깁기(규모화된 콘텐츠 남용)' 정의에 정면으로 걸립니다.

**(B) 서술형 '가이드' 페이지 — 유일한 원본 콘텐츠, 그러나 소량**

`/guide`는 부동산·청약·금융·의료·보육·학교·생활 7개 카테고리에 각 2편씩 **총 14편 내외**입니다. 실제 원문(예: "실거래가, 어떻게 읽고 활용할까?")은 도입→읽는 법→유의점→FAQ→참고자료 구조의 **약 800~1,000자 한국어 원문**으로, 품질 자체는 준수합니다. `/board`(임장ON 브리핑)는 공공기관 보도자료를 사실 위주로 정리한 것으로, 원본성은 (A)보다 낫지만 요약·재정리 성격이 강합니다.

### 3.2 핵심 문제 4가지

| # | 문제 | 구글 정책 매핑 | 근거 |
|---|---|---|---|
| 1 | **텍스트-데이터 비율이 극단적으로 낮음.** 상세 페이지에 봇이 읽을 고유 문장이 없음 | 스크래핑 / 규모화된 콘텐츠 남용 | 광교샛별 상세 페이지 실측 |
| 2 | **원본 콘텐츠 총량 부족.** 서술형 원문이 가이드 14편 수준 | (비공식) 20~30편 통설 미달 | `/guide` 실측 vs 커뮤니티 통설 |
| 3 | **부가가치가 '텍스트로' 표현되지 않음.** 반경 1km 시세·도보 16분·인프라 근접성 등 훌륭한 해석 재료가 있으나 문장 설명이 없음 | 집계에 '고유 이점' 부재로 인식 | 상세 페이지 구성 분석 |
| 4 | **대량 얇은 페이지가 그대로 색인 대상.** 사이트 평균 품질을 끌어내림 | 규모화 남용/도어웨이 의심 신호 | 사이트맵·페이지네이션 구조 |

### 3.3 동일 유형 비교 사례 — '주거나침반(jugeo.co.kr)'

이번 리서치에서 **거의 판박이 사례**를 확보했습니다. LH·SH·GH 공공임대주택 공고를 단지·건물 단위로 재가공해 제공하는 '주거나침반(jugeo.co.kr)' 운영자가 2026년 6월 애드센스 커뮤니티에 올린 글에서, 반복적인 '가치 없는 콘텐츠' 거절을 호소하며 스스로 다음을 원인으로 지목했습니다(support.google.com 스레드 438918883).

> *"데이터와 표 위주로 UI가 구성되어 있다 보니, 서술형 텍스트(문장)의 절대적인 분량이 부족해서 크롤러가 '콘텐츠가 없다'고 인식할 가능성", "데이터를 가공해서 보여주는 방식이 봇에게는 단순 크롤링된 스팸 사이트와 기술적으로 다르게 보이지 않는 것인지…"*

**imjangon과 사업 모델·기술 구조·거절 사유가 사실상 동일**합니다. 이 사례는 imjangon의 거절 원인 가설을 강하게 뒷받침하는 동시에, "데이터 재가공 서비스는 서술형 텍스트 부가가치를 반드시 보강해야 통과한다"는 방향성을 확증해 줍니다.

### 3.4 이미 잘 되어 있는 것 (문제가 아닌 항목)

- **정책 페이지 완비**: About(서비스 소개)·데이터 안내·FAQ·이용약관·개인정보처리방침·문의·사이트맵 존재 → table stakes 충족.
- **출처 투명성**: 모든 데이터 블록에 공공기관 출처 명시(국토부·보건복지부 등) + `/data-source` 페이지. E-E-A-T의 신뢰성(Trust)에 유리.
- **가이드 품질**: 14편의 원문은 구조·정확성이 준수. **확대의 좋은 출발점.**
- **기술적 크롤 신호**: `robots: index, follow`, OG 태그·사이트맵 정상.

→ 결론적으로 imjangon에 필요한 것은 사이트 재건축이 아니라 **"원본 텍스트 부가가치"라는 한 가지 축의 집중 보강**입니다.

## 4. 개선안 — 우선순위별 실행 계획

핵심 전략: **"봇이 각 페이지에서 사람이 쓴 것 같은 고유한 해석 텍스트를 읽게 만들되, 동시에 얇은 페이지의 색인 비중을 줄여 사이트 평균 품질을 끌어올린다."**

### P0 — 즉시(재신청 전 필수)

**P0-1. 상세 페이지 템플릿에 '데이터 해석형 서술 단락' 삽입**
표를 반복하는 문장이 아니라, **보유 데이터로만 만들 수 있는 비교·평가·맥락 문장**을 3~6문장 자동 생성합니다. 단순 치환형(스팸 위험)이 아니라 조건 분기 + 수치 해석형으로 설계하세요.

- 예(어린이집): *"광교샛별어린이집은 정원 69명 대비 현원 57명으로 충원율 83%로, 인근 1km 내 어린이집 평균보다 대기 수요가 높은 편입니다. 만 0세 대기 35명으로 영아반 경쟁이 특히 치열합니다. 도보 16분 거리 신분당선 상현역과 반경 500m 내 카페 8곳·병원 2곳이 있어 영유아 동반 생활 인프라는 양호합니다."*
- 예(아파트): 최근 실거래 추세(상승/하락/거래량), 동일 생활권 대비 가격 위치, 학군·역세권 해석.
- **주의**: 이 텍스트는 "표를 문장으로 바꾼 것"이 아니라 **비교·판단·맥락(사이트만의 편집 관점)** 을 담아야 '고유 이점'으로 인정됩니다. 무의미한 템플릿 문장 대량 복제는 오히려 규모화 남용 신호가 됩니다.

**P0-2. 서버사이드 렌더링(SSR) 보장**
Next.js 사용 사이트이므로, 위 해석 텍스트와 핵심 데이터가 **자바스크립트 실행 없이도 HTML에 렌더링**되는지 반드시 확인하세요. 봇이 빈 SPA로 인식하면 "콘텐츠 없음"으로 직결됩니다. (Firecrawl 크롤 시 텍스트가 잡혔으므로 현재 SSR은 대체로 동작 중으로 보이나, 신규 해석 단락도 동일하게 SSR 경로에 포함시켜야 함.)

**P0-3. 가이드 콘텐츠 1차 확대(→ 20편 이상)**
현 14편을 **최소 20편, 목표 30~40편**으로 늘리고, 각 편을 800자 이상 심층화. 신규 주제 예: 전월세 계약 체크리스트, 등기부등본 보는 법, 재건축·재개발 단계, 취득세·양도세 기초, 학군 vs 통학구역 차이, 어린이집 입소 가점 계산 등.

### P1 — 2~4주 내

**P1-1. 얇은 페이지 색인 다이어트**
- 데이터가 거의 없는 엔티티(폐업/정보 없음), 순수 페이지네이션 셸, 파라미터 중복 URL은 **`noindex`** 또는 canonical 정리.
- `sitemap.xml`에는 **해석 텍스트가 실린 알짜 페이지만** 포함.
- 효과: 사이트 전체의 "평균 페이지 품질"이 올라가 규모화 남용 의심을 낮춤.

**P1-2. 에디토리얼 '허브' 페이지 신설**
사람이 직접 쓴(또는 데이터 기반이되 편집자 관점이 강한) 분석 페이지를 만듭니다. 예: "2026년 광교 생활권 시세·학군 총정리", "수원 영통구 어린이집 지도" 같은 지역·주제 큐레이션. 이런 페이지는 상세 페이지들을 내부 링크로 묶어 **토픽 권위(topical authority)** 를 형성하고, 봇에게 "이 사이트엔 사람이 만든 고유 분석이 있다"는 강한 신호를 줍니다.

**P1-3. 상세↔가이드 상호링크**
각 상세 페이지에서 관련 가이드로("입소 대기란? → 어린이집 입소 대기 가이드") 문맥 링크. 사용자 체류·크롤 깊이·내부 링크 구조 동시 개선.

**P1-4. E-E-A-T 신호 강화**
- 운영 주체·운영자 정보, 데이터 수집·갱신 **방법론 페이지**, 각 페이지 **"기준일/최종 업데이트" 날짜** 노출(가이드에는 이미 '기준일' 표기 있음 → 상세 페이지에도 확대).
- 문의/피드백 경로 강조.

### P2 — 지속·전략

**P2-1. 사이트 연령·트래픽 확보 후 재신청**
신규/저트래픽이면 콘텐츠와 무관하게 거절될 수 있으므로, **최소 1~3개월 운영 + 자연 검색·SNS 유입**을 확보한 뒤 재신청. 재신청은 성급히 반복하지 말고 실질 변경 후 2~3주 간격.

**P2-2. 대안 광고 네트워크 병행 검토**
애드센스 승인 지연 시 신규·중소 트래픽 사이트를 받아주는 **Ezoic** 등을 과도기적으로 활용. 트래픽이 커지면 애드센스 승인도 쉬워집니다(Toolpod).

**P2-3. 콘텐츠 원본성 지속 관리**
자동 생성 해석 텍스트가 전 사이트에서 지나치게 동일 패턴이 되지 않도록 주기적으로 문구 다양성·정보 갱신을 점검. "AI 대량 생성"으로 보이지 않도록 편집 관점을 유지.

## 5. 결론

imjangon.co.kr의 애드센스 'thin content' 거절은 **콘텐츠가 무가치해서가 아니라, 사이트의 진짜 가치(공공데이터의 생활권 맥락 재조합)가 "크롤러가 읽을 수 있는 고유한 원본 텍스트"로 표현되지 않았기 때문**입니다. 구글의 공식 스팸 정책(규모화된 콘텐츠 남용·스크래핑)은 "피드를 고유 이점 없이 재현하는 대량 페이지"를 정확히 겨냥하며, 동일 유형의 '주거나침반' 사례가 같은 벽에 부딪힌 사실이 이 진단을 뒷받침합니다.

해법은 사이트를 갈아엎는 것이 아니라 **한 축의 집중 보강**입니다. ① 상세 페이지마다 데이터 기반 해석 문장을 더해 '고유 이점'을 텍스트로 증명하고, ② 가이드·허브 같은 원본 에디토리얼을 20~40편 규모로 키우며, ③ 얇은 대량 페이지의 색인 비중을 줄여 평균 품질을 올리고, ④ 연령·트래픽을 확보해 재신청하는 것. 이미 정책 페이지·출처 투명성·기본 크롤 신호가 갖춰져 있으므로, **"사람에겐 유용한 데이터"를 "봇도 가치를 읽는 원본 콘텐츠"로 전환**하는 작업에 집중하면 승인 가능성은 실질적으로 높아집니다.
