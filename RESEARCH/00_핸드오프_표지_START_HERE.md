## 1. 30초 요약

- imjangon이 애드센스 **'가치 없는 콘텐츠'로 거절**된 원인은 콘텐츠 품질이 아니라, 대다수 페이지가 **공공데이터를 표·수치로 재배치했을 뿐 "크롤러가 읽을 고유 원본 텍스트"가 없어서**입니다.
- 확인된 사실: **imjangon은 SSR이라 크롤은 잘 됩니다**(문제 아님). 문제는 오직 **"가치로 인정받는 신호"** 두 가지가 비어 있는 것 — ① **데이터 해석 문장**, ② **출처·신선도 구조화 데이터**.
- 참고로 동종 서비스 **ayo.pe.kr**은 CSR(더 불리한 렌더링)인데도 **광고가 실제 게재 중인 것으로 확인**됨(정황상 애드센스 승인) → 렌더링이 아니라 위 두 신호가 관건임을 방증.
- **해법**: 사이트 재건축 X. 각 상세 페이지에 **①해석 단락 + ②출처 JSON-LD**를 얹고, **얇은 페이지는 noindex**. 이미 SSR·엔티티 스키마가 좋아서 두 칸만 채우면 됩니다.

## 3. 비협상 원칙 (반드시 지킬 것)

이 5가지를 어기면 개선이 오히려 **역효과(규모화 남용 신호)** 가 납니다.

1. **표를 문장으로 바꾸지 말 것.** 반드시 **비교·추세·파생 판단**(또래 대비, 순위, 비율, 방향)을 담는다. "정원 69명입니다"(X) → "충원율 83%로 인근 평균보다 높다"(O).
2. **동의어·어순만 바꾼 문장 대량 생성 금지(synonym spinning).** 변형은 **데이터 결론이 달라질 때만**. 랜덤 문구 셔플 금지.
3. **데이터 부족 페이지는 억지 서술 금지 → 서술 생략 + noindex.** (프로즈 없음과 noindex는 항상 짝)
4. **해석 프로즈와 JSON-LD는 함께 적용.** JSON-LD만으로는 thin이 안 풀린다(신뢰 신호일 뿐).
5. **화면에 없는 정보를 스키마·프로즈에 넣지 말 것.** 표시값과 구조화데이터 값 일치(불일치는 cloaking·스팸).

## 4. 관리자가 확정해야 할 "열린 항목" (설계로 대체 불가)

아래는 내부 데이터·정책을 아는 담당자만 채울 수 있습니다. 구현 전 확정하세요.

- [ ] **카테고리별 `data.go.kr` 데이터셋 실제 숫자 ID** — JSON-LD `sameAs`에 삽입(모르면 생략, **추정 금지**).
- [ ] **데이터셋별 라이선스** — 대부분 공공누리(KOGL)이나 실제 표기 확인.
- [ ] **`dateModified` 동기화** — 각 카테고리 공공데이터의 **실제 갱신 기준일**을 스키마에 연결(가짜 최신화 금지).
- [ ] **색인/noindex 카테고리 최종 결정** — 편의점·카페·음식점 등 초경량은 기본 noindex 권장(개별 색인은 thin 위험, 다른 페이지의 인프라 근거로만 노출).
- [ ] **벤치마크 사전집계 배치** — 지역·유형별 중위/분위 통계(또래 비교의 근거). 기존 데이터로 계산.
